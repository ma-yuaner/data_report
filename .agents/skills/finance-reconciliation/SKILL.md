# 财务收入成本核对

先判断用户要调整规则、重算、交付资料还是开发看板。最新明确口径优先；读[规则与执行入口](references/rules-and-pipeline.md)中对应部分，复用已有阶段，避免重复读取3.7GB原Excel或每次生成新脚本。

## 始终守住的事实

- 原Excel只读；保存文件大小/mtime及文件、Sheet、原始行号。Parquet保存原始数值字符串，清洗/标签/核算结果独立分层并保留旧版本。
- 收入、成本分别汇总，先在双方各自压缩到匹配键，再关联；一对多/多对多不做原始行笛卡尔关联。跨月允许累计匹配，月份关系单独打标签。
- 差异绩效以会计业务单号匹配结算差异单号，走独立通道，不再重复匹配票号。缺少键不互相匹配。
- 金额用精确Decimal；空值、错误、单边缺失不补0。差额为会计减结算。系统分类与财务人工确认分别保存。
- 标签可重叠。用户2026-10-27最终明确：结转按票号在收入/成本方向内匹配，只打标签，不剔除、不扣减、不改变双方金额或差额。结转应收取账务金额CNY，应付取账务基本金额，引用金额不能跨匹配项累加。
- “2025归属＋结算全额／会计调账”是比较基础差异标签，不直接推断为汇率、已核对正确或应排除。出票/改签用实际数据来源“YYYY年M月报表”识别归属年月，其他有业务日期的按业务日期；不虚构具体日，不用文件月份、原出票日、航班日或付款时间替代。
- 交付优先总览＋收入/成本分类横向CSV，双方金额及差额在前，来源位置和人工结论栏在后；保留正确和异常全部结果。不要默认生成94份项目Excel。
- 大数据分批导出，每CSV最多50万数据行；宽行不反复全量排序，来源定位仅对多笔聚合，一对一直接取来源。内存上限与执行并发显式设置；超限报告原因，不截断成完整结果。
- 变更后独立核对新增/排除行数、对应金额、整体/按月合计、匹配项覆盖、文件链接和压缩包完整性。只验证本次影响，原始数据/临时测试不提交Git。

## 工程与交付边界

此skill供开发Agent复用规则，不是网站的运行引擎。上线后使用固定后端程序执行，不为逐行核对调用AI。用户只要求方案或尚未确认关键口径时，继续盘点/转存/文档，暂停依赖该决定的重算。

网站方向：上传批次 → 后台转存与版本化核对 → 与业务分析一致的总览/筛选/下钻 → 人工核实留痕 → 导出。复用认证、权限、文件存储和导出任务，不扩张为通用低代码加工器。旧工作台归档须保留代码、历史数据和恢复说明；下线页面与停止worker分别记录，不能声称仅搬文件就降低运行负载。
