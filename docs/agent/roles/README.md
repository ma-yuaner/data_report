# 角色入口与使用回执

更新：2026-10-20。来源：用户要求为每个开发角色命名，支持后续单独增强能力，并能看见是否使用。初始能力沿用项目现有职责。

## 固定名字与能力卡

| 名字 | 稳定角色ID | 负责什么 | 能力卡 |
|---|---|---|---|
| 明策 | product | 先判断紧急程度/难度，裁剪流程与测试；范围明确可直接开发，保留高级产品与README能力（v4） | [产品能力卡](product.md) |
| 绘景 | ui | 扁平化极简、信息布局、交互与AI工作台状态（v2） | [UI能力卡](ui.md) |
| 星桥 | frontend | 页面实现、状态、接口接入、前端验证 | [前端能力卡](frontend.md) |
| 磐石 | backend | API、服务、数据访问、权限与后台任务 | [后端能力卡](backend.md) |
| 明鉴 | qa | 必要验证、本地外部连接、test不入Git、测试群效果/计时与回执；先确认四位开发中的申请人，不@（v3） | [QA能力卡](qa.md) |

这些名字用于本项目的角色配置。默认由当前主会话按需承担相关职责，不创建五个常驻进程或独立聊天。启动独立子代理或并行工作需要明确的相应授权；名字本身不授予此权限。[根AGENTS.md](../../../AGENTS.md)定义共同边界和交付规则，能力卡补充具体检查要求。

## 怎么知道是否使用

1. 开工列出计划角色，计划不记作已使用。
2. 实际采用某角色能力时先说明，例如：`【角色启用：星桥｜前端｜主会话】实现筛选条件继承。`
3. 单独启动子代理时，只有工具调用成功才标记`独立子代理`，给出实际返回的标识和任务。启动失败、进行中、返回结果分别如实说明。
4. 交付简要列出实际角色和产物，剩余角色标记未启用；独立子代理是否启动单独明确。不将同一主会话的不同视角描述为独立人员互审。
5. 有实质进展的任务在[工作流](../workstreams.md)保留角色使用方式、产物与证据。普通简短问答按需使用，不强制走完五个角色。

可使用以下简短回执：

```text
角色使用：明策（主会话，需求与验收范围）；星桥（主会话，页面实现）；明鉴（主会话，回归验证）。
未启用：绘景、磐石。独立子代理：未启动。
```

## 怎么增强能力

用户可以直接按名字提出要求，例如“加强明策：以后新增需求都要列出用户场景、反例和验收标准”，或“加强明鉴：重点检查NULL/0、越权和重复提交”。

- 将明确的新要求更新到对应能力卡，版本递增，记录日期、来源、适用范围；必要时补充知识入口或例子。
- 保留有效旧规则；替代关系写清楚，遇到业务口径冲突由用户/业务负责人决定。
- 增强通过新增工作规则、知识来源、示例和验收标准落实。版本变化表示要求更新，实际效果用后续任务证据验证。
- 未经要求不将新规则推广到所有角色，不记录凭据或原始个人数据，不据此扩大任务授权。
- 更新角色卡后按项目约定做文档检查、提交并推送两端，默认不查询或等待CI。

新会话先从[项目入口](../README.md)读取上下文，再按任务或用户点名读取相关能力卡；不要求每次读取全部角色文件。
