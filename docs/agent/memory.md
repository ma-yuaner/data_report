## GDS必须保留的业务口径

- 公司当前查定比：非`*_MPIS`查询量 / 出票`seg_num`，包括NDC查询；不能套用行业含义自行改成PNR或生单成功数。
- `flag=1`出票；历史NULL暂按1；`flag=0`订位单独分析。订位和出票是两种归属，不能相加，也不能从日汇总证明具体订单换配置。
- 服务表`bi_gds_resource_metric_day`中`MP_TOTAL`用于正式比率；`API_GROUP`用于MP、MPIS、NDC接口质量；两类行不能叠加。
- OTA无查定比；查询、验价、生单各有自己的成功率分母，不当作一批订单的转化漏斗。
- 日表不含今天；现有Hive航线表无航段分母和标准错误原因，只能做请求与阶段质量定位，不能算航线查定比。
- 首阶段人工确认策略、技术执行回传；先复盘白名单和MPIS调整后的查定比变化，自动上下线后置。

## 容易误判的地方

- 当前ETL用“当日存在航段记录”推定细分缺行是0；这不是全批次同步完整证明。真实分析和自动化前要核验批次与覆盖。
- 页面目标值来自配置，规则阈值来自规则版本；尚非同一配置源，报告必须写清使用哪一个。
- 重跑日规则会更新同一事件的证据；复盘不能只依赖事件当前快照恢复首次命中值。
- 航线列表默认Top500、最多31天；截断列表之和不代表全量结果。航线查询预计30–60秒是提示，不是时延保证。
- 白名单、配置和治理复盘部分页面是localStorage演示；正式事件和工单在监控中心。看到页面状态变化不能证明交易系统执行。
- SQL文件存在不代表线上已执行；代码存在不代表调度已配置或通过业务验收。
- 平台站点航线异常V1已固化静态评估与开发清单，见`docs/product/gds-route-anomaly-data-readiness-v1.md`。用户确认验价/生单请求同时为0、先站内提醒、经理每日仅汇总。小时源保留目标维度但尚未验数；日表丢平台/站点，分钟DDL与产出有差异，查询机场为空，不能直接按机场匹配三阶段。3/7窗口和样本门槛尚未正式确认，本轮不开发、不查生产库。
