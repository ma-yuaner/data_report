# 主代理调度与高效协作 · v2

2026-10-24。v2来源：用户要求精简代理与检查；优先于v1的并行数量和角色编排建议。本文件是可复用的工作规则，不是模型训练、客户端配置已修改或节省比例证明。

## 开发任务开头的执行约束（v2）

控制token用量：先由主代理检查相关文件并实施；小改动、单文件、明确bug不启动子代理。复杂功能至多委派一个实现代理，主代理负责理解需求、协调、集成和汇总。需要额外把关时，在实现代理结束后，再至多启动一个审查代理，只看最终diff和关键风险；任一时刻最多一个活动子代理，子代理不得继续派生代理。只有任务能明确拆成互不依赖、文件归属不重叠的工作才委派，不让多个代理重复扫描整个仓库、重复写方案或同时编辑同一文件。代理仅返回发现的问题、涉及文件、必要建议或实现所必需的差异/证据，不重复任务背景。检查先覆盖与改动直接相关的风险，通过后不重复扩大范围；金额、权限、写库、生产控制等必要安全验证仍保留。

## 谁负责与何时调用

- 当前会话是主代理：负责范围、风险、拆分、模型档位、唯一契约、集成、验证和交付。明策/绘景/星桥/磐石/明鉴是职责，可由主会话兼任；点名不自动开五个代理。
- 用户允许按上述v2边界委派，不越权扩展业务、生产或通知动作；不为了展示角色数量而调用。
- 默认主代理单独工作；确需委派时最多同时一个子代理，实现与额外审查顺序执行，禁止子代理再分包。
- 一个文案/局部样式、明确单点修复、纯命令执行、强顺序依赖、多个角色争写同一文件、等待同一外部条件：留在主代理。不能把模型调用替代已有确定性脚本。
- 先用一句话判断紧急程度/难度/风险/最小范围；有实质争议再展开方案，不新增固定长PRD、五角色打卡或无关全量测试。

## 模型与推理分档

下面是用户偏好的执行策略，不是通用性能排名或已启用的全局配置。模型、推理强度、输出长度分别控制，高强度不等于长输出；只用当前工具实际支持且获授权的组合。

| 任务 | 默认请求档位 | 升降条件 |
| --- | --- | --- |
| 明策复杂方案、磐石架构/重大取舍 | gpt-6-astra / ultra（不支持则最高可用档） | 只在有实质设计决策时使用；不为文案或已确认方案重新做最高档规划 |
| 绘景交互方案 | gpt-6.1-sol / high | 跨流程复杂方案升Astra；明确组件/文案差异可降执行档 |
| 星桥/磐石常规实现 | gpt-6.1-sol / medium | 契约明确再执行；复杂状态、跨层冲突或验证暴露未知时升high，重大取舍交高档方案 |
| 窄范围扫描、文案/样式、机械核对 | gpt-6-luna / medium，足够简单时low | 发现歧义或超出边界即回报，不靠轻量模型猜复杂业务 |
| 明鉴风险审查 | gpt-6.1-sol / high | 确定性检查直接跑已有命令；金额、鉴权、迁移、生产控制等关键风险不得仅按“代码任务”降档，必要时Astra复核 |

- 当前主会话模型由客户端/宿主配置决定，不能靠角色切换声称已改变。只有真实启动成功才报告子代理；记录工具返回标识、请求的模型/推理参数、任务和结果，实际模型元数据不可见时不冒充核验了底层执行或计费。
- 完整历史继承按工具限制可能固定沿用主模型；需要指定不同模型时，仅在工具支持下使用独立上下文并提供最小完整任务包。不可跳过适用AGENTS/技能的必读要求，也不把聊天摘要当源码事实。
- 不可用时说明限制，选择获授权且支持的替代组合；不静默升级费用档、不反复失败重试，也不编造切换成功。本文件不新建全局模型配置或自动模型路由服务。

## 一次交接，只传必要差异

任务包最多六类必要信息：目标、输入/证据路径与版本、约束/禁止事项、归属文件、验收/现有命令、未决项。已在同一上下文且未变的资料只引用，不整段重贴；新代理必须给足必要上下文与正确仓库路径。

子代理返回改动或结论、证据、风险/待办三部分；默认短摘要，不返回全文件/全日志。需要复现时给精确路径/错误/命令，不能为了短而省关键事实。主代理自己复核依赖，不将“已启动/已返回”写成“已验证通过”。

- 共享API/状态/字段先明确唯一契约和负责者；并行只分开归属文件，集成前核对依赖。UI不重定业务，前端不冒充服务端鉴权，后端自检不替代独立QA证据。
- 先定位已有脚本/组件/服务与固定命令，确有缺口才最小补齐；不每轮重新造脚本、重复全库扫描或输出整份提示词。搜索先rg，按入口缩小范围。
- 证据复用必须同版本或确认相关实现/契约/环境未变；标原版本、范围、失效条件。源码、契约或配置变化后只补相关检查，旧证据不冒充新执行。用户明确全流程或高风险链路时保留应有覆盖。
- 失败先分类为产品、测试夹具、配置/权限或外部工具问题；有新定位依据才做一次定向返工。同因再次失败由主代理接管定位/必要升级，不让代理反复互抛，也不绕过禁用设置。关键业务/权限选择缺失时问用户。

## 质量与成本一起看

不承诺“最少token”或无基线的节省率。能取得真实usage时记录输入/输出、调用/返工及验证结果，同范围同验收比较；取不到就标未知。代理数、阅读范围、重复调用、返工和检查次数仅是过程信号，不换算成精确token或费用。主代理保留必要的进度沟通与安全核对，不以沉默/省略证据冒充高效。

最小交付：变化、验证/未验、提交推送、风险/下一步。发版继续确认申请人/项目目标/通知渠道，复用现有脚本且同任务一次、不@、未知回执不自动重发；Git推送不等于服务器部署。本轮只改角色/文档时做文档静态检查，不重跑ERP/业务全量测试。

## 规则验收例子（行为预期，不是模型质量跑分）

| 输入场景 | 应有行为 |
| --- | --- |
| 改一个按钮文案 | 单代理、复用组件、局部核对，不开五代理/重做PRD |
| 仅设计复杂需求 | 高档方案、明确取舍/关键假设；不改业务代码、不擅定生产动作 |
| 前后端可独立实现 | 主代理定共享契约和文件归属后再并行，不各造一套字段 |
| 改权限/金额/迁移 | 保留高风险审查和针对性测试，不因省token降掉安全边界 |
| 只更新角色规范 | 检查版本/链接/边界与差异，不重取生产数据或重跑业务全量 |
| 工具禁用或同因两次失败 | 单列未验/接管定位，不绕过设置、无限重试或谎报成功 |
| 没有真实token回执 | 报未知与过程证据，不宣称节省百分比 |
