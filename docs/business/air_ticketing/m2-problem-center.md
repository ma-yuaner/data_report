# M2 经营问题中心

更新时间：2026-09-14

状态：已实现；业务估算口径

## 目标

经营总览回答“结果是多少”，问题中心回答“当前哪些记录需要继续调查”。首版只识别四张已接入宽表中利润小于 0 的业务记录。

## 识别规则

| 业务 | 时间字段 | 利润字段 | 业务过滤 |
|---|---|---|---|
| 出票 | MySQL `operator_date` / Hive `issue_ticket_time` | `issue_profit < 0` | 与经营总览出票口径一致 |
| 退票 | `apply_datetime` | `refund_profit < 0` | 允许的 `business_type_desc` 且供应退款操作人不为空 |
| 改签 | `change_issue_time` | `change_profit < 0` | 与经营总览改签口径一致 |
| 增值 | `create_time` | `profit < 0` | `aux_status='已购买'` |

默认查询今日，可切换昨日、本月、本年或自定义闭区间。四类查询全部成功时才展示总体负利润记录数和负利润金额；任一来源失败时不把缺失值当作 0。

## 页面输出

- 总负利润记录数、负利润金额、涉及业务数、数据完整性；
- 出票、退票、改签、增值的负利润记录数、金额和占比；
- 按单条利润从低到高的 Top 20 证据记录；
- 订单/事件编号、票号、平台、供应商、航司、操作人和发生时间。

人员字段用于回查业务过程，不代表责任认定。负利润也不自动等同财务最终损失；对赌、任务、返点、汇率、售后冲销和 ADM 等原因将在对应数据确认后逐步加入。

## 性能策略

- 为兼容当前 MySQL 版本，每类业务分别执行轻量汇总和 Top 20 明细查询；
- 默认今日，避免首屏扫描全年；
- API 使用短时缓存；
- 当前默认读取 MySQL，必要时人工切回 Hive，不进行跨源自动补数；
- 后续高频访问或历史范围变慢时，再将每日问题汇总写入 MySQL ADS，API契约保持不变。
