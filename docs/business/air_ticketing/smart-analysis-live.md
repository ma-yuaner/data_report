# 智能分析：MySQL真实数据

来源：用户于2026-10-09确认先建设智能模块；2026-10-15要求补充与业务综合分析一致的智能综合分析，并与投放任务打通。菜单采用“智能分析 → 智能整体分析 → 综合分析/智能总览/维度分析/出票明细”三级结构。

状态：页面、接口已切换到MySQL 5.7的年度智能指标表和出票明细表，复用现有`sibebid`连接；需以同步后的日期范围完成数据结果验证。

## 数据来源

- `sibebid.bi_smart_issue_dimension_year`：出票日期、起飞日期、进单日期与完整维度组合粒度的年度指标表，用于总览、趋势、筛选项和维度分析；
- `sibebid.bi_smart_issue_detail_year`：一行一个`issue_id`的年度出票明细表，用于分页明细和智能任务证据。

智能模块固定读取MySQL `sibebid.bi_smart_issue_dimension_year`和`sibebid.bi_smart_issue_detail_year`，不跟随经营模块的`DATA_MODE`切换，也不静默回退Hive或演示数据。浏览器只调用Flask接口，不能直接连接数据库。

## 页面与接口

| 页面 | 路由 | 接口 |
|---|---|---|
| 智能综合分析 | `/smart-analysis/comprehensive` | `GET /api/v1/smart-analysis/comprehensive` |
| 智能总览 | `/smart-analysis/overview` | `GET /api/v1/smart-analysis/overview` |
| 维度分析 | `/smart-analysis/dimensions` | `GET /api/v1/smart-analysis/dimensions` |
| 出票明细 | `/smart-analysis/details` | `GET /api/v1/smart-analysis/details` |
| 筛选建议 | 四页共用 | `GET /api/v1/smart-analysis/filter-options` |

四个页面共用出票、首段起飞、进单日期以及航司、平台、站点、政策员、机场、国家、乘客类型、利润区间等条件。出票日期不是必填项；三类日期可任选一个或多个，但至少要有一组完整的开始、结束日期，多组范围同时选择时取交集。维度分析支持表中全部已确认维度的组合、排序和后端分页；明细支持票单范围、字段选择、后端分页和出票证据抽屉，表格字段统一按维度/描述字段在前、数量金额与布尔指标在后排列。

票单范围的“未参与”按当前智能类型判断：智能降舱和智能废票分别以各自参与标记不为1（包含NULL）认定；智能整体需降舱、废票均未参与。

维度分析可按当前账号在浏览器保存“维度+显示指标+排序”命名模板；出票明细可保存命名字段模板。模板支持选用、同名覆盖和删除，退出再登录仍保留，不写入业务数据库；更换浏览器或清理本地站点数据后不会自动迁移。

智能分析所有Excel导出统一使用数量保护：30万条及以下直接导出，超过30万条弹窗提醒耗时较长且可能失败，建议缩小日期或筛选范围；超过90万条禁止导出。大导出使用MySQL分批读取和Excel低内存写入，不修改数据库结构。

角色菜单权限将智能整体分析拆分为`smart.comprehensive`（智能综合分析）、`smart.overview`（智能总览）、`smart.dimensions`（维度分析）和`smart.details`（出票明细），管理员可在“角色与功能”中分别选择二级页面。历史`smart.home`授权在读取时自动兼容为上述四页，不需要修改数据库结构。

## 智能综合分析与投放联动

智能综合分析复用智能ADS指标，不重复建设指标表；投放覆盖来自`smart_placement_task`、`smart_placement_execution`和`smart_placement_order_match`。首版支持按平台、航司、航线、站点、产品类型和订单来源对比出票量、航段数、智能参与、智能使用、使用率与智能利润，同时显示当前账号可见的投放任务和命中订单。

页面严格区分未投递、草稿、审核/认领/执行流程中、监控中、已停止/结束。只有投放登记成功并进入`MONITORING`才显示“监控中”；创建草稿不等于已经投递。任务未限制站点、航线、产品或订单来源时，代表覆盖该维度下全部值，因此任务数不能跨维度行相加。

“分析此项”支持在平台、航司、航线、站点、产品类型和订单来源之间逐层关联下钻。页面通过分析路径保留每一级条件，当前层的经营指标、投放覆盖、出票明细以及创建投放机会均使用同一组累计条件；可通过面包屑返回任意上级或清空下钻。有创建权限的账号可把当前日期、完整分析路径、出票量和利润带入投放机会表单。任务详情仍由投放政策页面负责，综合分析不复制审核、认领和登记逻辑。

投放任务没有限制站点、航线、产品类型或订单来源时，视为覆盖这些维度的全部值；多层下钻时必须同时满足任务已填写的所有限制条件，不能仅按最后一级维度关联。平台与航司仍按任务明确值匹配，不把空值解释为全量覆盖。

投放联动查询必须沿用智能投放数据权限；普通账号不能借综合分析看到权限范围外的任务。投放表未部署或暂时不可用时，只降级投放覆盖区域，智能经营指标仍然可查询。首版不计算“机会评分”，也不把任务存在误判为智能增量收益。

本版本不新增数据库表和ETL。新增菜单权限为`smart.comprehensive`；历史`smart.home`授权自动包含该页面。

趋势页先选择统计日期轴（出票、首段起飞或进单）。日趋势从该日期轴的截止日往前固定取30天，月趋势取截止月在内的最近12个月；如果页面没有填该日期轴的结束日，截止日使用当前业务日。其他已选日期范围和业务筛选仍同时生效。

## 指标口径

- 全部出票、预估利润、总航段数、退票出票量直接汇总日指标表；
- 智能整体、智能降舱、智能废票分别汇总对应的参与、成功、使用和智能利润字段；
- 参与率=`参与出票量/全部出票量`；
- 成功率=`成功出票量/参与出票量`；
- 成功使用率=`使用出票量/成功出票量`；
- 参与使用率=`使用出票量/参与出票量`；
- 使用率=`使用出票量/全部出票量`；
- 智能单张利润=`智能利润/智能使用出票量`；
- 分母为0时比率为0；查询无源记录时指标为NULL并展示“暂无数据”，不能认定为真实零；
- 智能利润是使用智能票单的`issue_profit`之和，不是智能带来的增量收益。

明细中的整体参与为降舱或废票任一参与，整体成功为任一成功，整体使用以`smart_confirm IN ('智能降舱','智能废票')`为准。降舱、废票分别使用各自参与/成功标记及`smart_confirm`值。

## 数据边界

- 日指标表没有独立coverage行，当前只能区分查询成功有记录、查询成功无记录和查询失败；无记录不发布为真实零；
- `department_code/department_name`和`route_length_type`的源映射在表注释中仍标记待确认，页面只展示源表值，不自行推定；
- 金额为出票预估利润，非财务结算口径；
- 单次日期范围最多366天，每页最多100条；字段、分组和排序均由服务端白名单控制，筛选值使用参数绑定；
- 查询失败返回不可用状态，不显示旧数据或模拟数据。
