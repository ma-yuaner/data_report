# 机票业务分析规则

## 1. 分析前置检查

每次分析先明确：

1. 要支持什么业务决策；
2. 分析对象是订单、乘机人票、客票、航段、售后单还是金额事件；
3. 使用下单、出票、起飞、售后发生还是财务确认日期；
4. 使用原币还是统一本位币，汇率取值规则是什么；
5. 利润是预期、业务估算还是已结算；
6. 订单状态、取消、退票、失效和测试数据如何处理；
7. 返点、退款、结算、ADM 和增值数据是否完整；
8. 用户有权限查看哪些平台、部门、人员和金额。

缺少上述信息时，可以进行探索性分析，但必须标记假设，不能输出正式经营结论。

## 2. 标准分析路径

```text
业务问题
→ 决策目标
→ 指标与粒度
→ 数据来源与完整性
→ 总体结果
→ 平台/航司/政策/供应/人员拆分
→ 预期与结算差异
→ 异常订单或金额事件下钻
→ 根因证据
→ 可执行建议与验证方式
```

不要看到亏损后直接按单一维度排名。先区分收入下降、采购成本变化、返点未确认、让利增加、退改损失、增值变化、罚损和汇率影响。

## 3. 指标计算约束

- “订单数”“票数”“乘机人数”“客票数”“航段数”分别计算，不互相替代。
- 一张订单多乘机人、多客票、多航段时，先在原始粒度计算再汇总。
- 金额跨表关联后必须验证关联前后总额，防止一对多放大。
- 比例指标同时展示分子、分母和样本量。
- 平均处理时长同时给出中位数或分位数，避免极端值误导。
- 供应比价必须基于当时可用报价，不使用后来出现的价格评价历史选择。
- 人员绩效同时考虑业务量、复杂度、政策约束、系统失败和可控性。
- 相关关系不能直接表述为因果；根因结论需要订单或事件证据。

## 4. 利润分析输出

标准利润分析至少包含：

- 本期已结算利润及同比/环比基础；
- 预期利润与已结算利润差异；
- 收入、采购、佣金、支付、返点、增值、售后、ADM 分解；
- 缺失或待确认金额规模；
- 按平台、航司、政策、供应、出票方式和人员拆分；
- 亏损集中度及 Top 异常明细；
- 高风险收益和处罚单列；
- 可以验证的行动建议。

会议中提到的季度亏损趋势和 ADM 金额只能作为调查线索，在财务口径和期间范围确认前不能直接进入正式看板。

## 5. 业务建议边界

- 可以建议完善数据、调整监控、验证政策、优化比价、改进激励和降低风险。
- 涉及价格投放、退款处理、客户授权、Open 票、航变留单、自转非或规避平台规则时，必须提示需要业务、法务/合规和平台规则确认。
- 不提供通过隐瞒客户、虚构非自愿原因、重复退款或规避审计获得利润的方案。
- “利润高”不等于“业务健康”；需要同时观察可持续性、现金占用、投诉、ADM、规则依赖和数据可信度。

## 6. 结论表达模板

```text
结论：回答业务问题，不超过三点。
口径：说明粒度、时间、币种、利润阶段和过滤条件。
证据：列出主要驱动及对应金额/数量。
异常：给出可下钻的订单、政策或事件范围。
限制：说明缺失数据、待确认规则和可能偏差。
行动：给出负责人可执行、可验证的下一步。
```
