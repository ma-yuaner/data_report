# 智能投放业务评审原型

- 信息来源：用户于 2026-10-09 提供的智能投放业务设想
- 当前状态：用户于2026-10-09确认总体流程没有问题；当前制作纯前端模拟数据演示，字段与细节仍待业务反馈
- 原型文件：`docs/prototypes/smart-placement-review.html`

## 当前业务目标

### 投放政策

1. 数据部通过分析产生需要投放的政策机会，并进入待办池。
2. 依次由数据部经理、政策经理审核；审核通过后进入政策人员认领池。
3. 政策人员认领任务，完成投放后登记外部政策 ID、实际投放时间等执行结果。
4. 系统根据已投放内容匹配订单；匹配成功后向群内发送来单提醒。
5. 政策人员及时关注订单，并在系统中留下关注与处理记录。

### 收单情况

1. 查看命中投放政策的订单明细。
2. 提供匹配订单量、票数、预估利润、关注时效、待关注数量等基础分析。
3. 支持从政策查看收单结果，也支持从订单回溯命中的政策和负责人。

## 本次原型边界

本次仅新增一个独立静态 HTML 评审原型，使用模拟数据和前端交互。原型可演示新建分析机会、数据经理审核、政策经理审核、任务认领、投放结果登记、订单匹配、群提醒和收单关注。未增加正式菜单、路由、接口、数据库表、订单匹配任务、消息机器人或权限逻辑。

## 业务评审需要确认

1. 投放机会是只由分析规则自动产生，还是允许数据人员手工创建与补充。
2. 数据部经理、政策经理的审核顺序、驳回后的修改方式，以及是否允许撤回。
3. 哪些人员可以认领，是否允许转交、取消认领、多人协作以及超时自动释放。
4. 政策任务的优先级、期望完成时间和超时升级规则。
5. 投放成功与失败分别必须登记哪些字段；外部政策 ID 是否全局唯一。
6. 订单匹配所使用的平台、站点、航司、航线、舱位、日期、价格、产品等维度及其优先级。
7. 群提醒的接收范围、消息内容、频率，以及重复订单是否再次提醒。
8. “已关注”的完成标准、负责人确认方式、无人响应时的升级与关闭规则。
9. 收单分析中的订单数、票数、利润与关注时效采用什么业务口径。
