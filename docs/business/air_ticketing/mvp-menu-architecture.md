# 机票数据中心 MVP 菜单架构

## 当前 M1/M2 实施切片（2026-09-16）

> 来源：用户于 2026-09-15 明确要求新增一级菜单“风控分析”，并于 2026-09-16 明确要求补充“智能分析”一级入口、路由、页面和文档。菜单框架状态为已确认；具体风险指标、智能模型、分析规则与数据源仍待确认。

完整目标架构保留在本文后续章节，但当前可用数据只支持出、退、改、增利润。因此上线菜单先收敛为：

```text
企业数据中心
├─ 经营总览
├─ 业务分析
│  ├─ 出票分析
│  ├─ 退票分析
│  ├─ 改签分析
│  └─ 增值分析
├─ 风控分析（框架预留）
├─ 智能分析（框架预留）
├─ 问题中心
└─ 数据资产
```

- 经营总览回答四类业务利润和总预估利润；
- 出票分析已有平台、航司、供应商、组织维度和字段齐全度；
- 退票、改签、增值首版只展示业务量、利润、单笔利润、负利润记录和趋势；
- 风控分析先建立一级入口，用于后续承载 ADM、平台罚单、投诉与高风险售后；未接入前不展示模拟指标或零值；
- 智能分析先建立工作区，用于后续承载智能问数、经营诊断和主动预警；未确认指标、规则与权限前不输出生产结论；
- 数据资产展示实际表、指标定义和更新状态；
- 问题中心首版只识别出、退、改、增负利润，展示问题规模和 Top 证据记录；
- 全链路、通用明细查询等入口在数据和业务规则未到位前不展示；风控分析是当前建设计划中明确保留的预留入口。

后续只有当某类问题可由稳定数据回答时，才从以下目标架构中启用对应页面。

## 1. 产品目标

数据中心首先解决管理会议中的五个连续问题：

```text
经营结果怎么样？
→ 为什么会这样？
→ 问题集中在哪里？
→ 哪些业务明细可以证明？
→ 数据和口径是否可信？
```

菜单按管理决策路径组织，不按数据库、部门、图表类型或临时报表名称组织。

## 2. MVP 主菜单

```text
企业数据中心
├─ 01 经营驾驶舱
├─ 02 利润分析
├─ 03 机票全链路
├─ 04 问题中心
├─ 05 明细查询
└─ 06 数据资产
```

MVP 只保留六个一级入口。系统设置、用户权限和操作日志放在右上角管理入口，不占用业务主导航。

## 3. 页面职责

### 01 经营驾驶舱

回答：“公司机票业务当前经营结果怎么样？”

页面编排：

1. 数据更新时间、完整性和口径状态；
2. 销售、出票、利润、风险四组核心指标；
3. 收入—成本—利润趋势；
4. 利润驱动与拖累因素；
5. 平台、航司、供应的结构变化；
6. 当前最需要关注的问题；
7. 从问题直接进入对应分析页面。

首页只展示能推动管理决策的指标，不堆放所有部门数据。

### 02 利润分析

回答：“利润从哪里来，亏损由什么造成？”

MVP 页面采用三个页签：

- `利润全景`：预期、业务估算、已结算利润；
- `利润归因`：收入、采购、佣金、返点、售后、增值、ADM 等利润桥；
- `预期与结算差异`：定位后返缺失、退款未结算、汇率、处罚等差异。

平台、航司、政策、供应商、出票方式和人员均作为筛选或下钻维度，不拆成菜单。

### 03 机票全链路

回答：“利润和效率在业务哪个环节产生或损失？”

MVP 使用同一页面的生命周期页签：

- `售前·政策`：政策覆盖、收单、任务、预期利润和让利；
- `售中·出票`：出票量、成功率、耗时、供应选择、超亏和换供应；
- `售后·退改`：自愿/非自愿、退款、改签、航变、Open 和垫资；
- `结算·资金`：后返确认、退款到账、虚拟卡、账期和已结算利润；
- `增值服务`：行李、选座等销售、成本和净收入。

第一版合并成一个页面，业务成熟后再将高频页签拆成独立菜单。

### 04 问题中心

回答：“现在需要谁处理什么问题？”

MVP 分为：

- `经营异常`：利润突降、负利润订单、异常让利、返点缺失；
- `履约异常`：出票失败、出票超时、供应切换、退款超时；
- `风险异常`：ADM、平台罚单、投诉、高风险售后业务；
- `数据异常`：来源延迟、字段缺失、关联失败、口径待确认。

问题中心不是另一套统计报表。每条问题应包含影响金额/数量、归属环节、负责人、状态和明细入口。

### 05 明细查询

回答：“结论由哪些真实业务记录支撑？”

MVP 采用一个统一查询页面，通过对象类型切换：

- 订单/乘机人票；
- 客票/航段；
- 政策；
- 出票履约；
- 售后事件；
- 金额事件；
- ADM/处罚。

详细对象不分别占用主菜单。查询页承担看板下钻、条件筛选、字段解释和受控导出。

### 06 数据资产

回答：“数据部到底有什么数据，这些数据能不能用？”

这是解决“数据部没有数据”认知问题的关键页面，MVP 分为：

- `数据覆盖地图`：按业务环节展示已有、建设中、缺失和受限的数据；
- `指标口径`：指标定义、粒度、时间口径、负责人和确认状态；
- `业务术语`：统一渠道、供应、出票、结算等概念；
- `数据更新状态`：来源系统、最近更新时间、延迟和质量状态。

数据资产页面不暴露数据库密码或无意义的技术表名。面向业务展示“能回答什么问题、由谁负责、可信到什么程度”。

## 4. 顶部全局能力

所有页面共享：

- 统计周期；
- 利润阶段：预期/业务估算/已结算；
- 销售平台；
- 航司；
- 供应商；
- 国内/国际；
- 数据更新时间和口径状态；
- 当前用户和管理入口。

人员、PCC、航线、出票方式等高基数条件放入页面高级筛选，避免全局区域过载。

## 5. 会议使用路径

```text
经营驾驶舱发现利润下降
→ 利润分析识别主要拖累项
→ 机票全链路定位发生环节
→ 问题中心查看异常集合
→ 明细查询核对订单/客票/金额事件
→ 回到业务系统处理
```

每个页面必须提供下一层入口，不能让管理者看到一张图后仍然要求数据部现场重新拉数。

## 6. 数据未接入时的展示规则

- 没有数据时显示“待接入”或“来源缺失”，不能显示为 `0`；
- 口径未确认时显示“待确认”，不能展示为正式 KPI；
- 数据延迟时保留最后更新时间并显示延迟状态；
- 示例数据必须明确标记为“演示数据”；
- 不完整指标不得进入经营驾驶舱，只能在数据资产或建设进度中展示。

## 7. MVP 暂不建设

- 自助拖拉拽 BI；
- 用户自定义 SQL；
- 自定义报表设计器；
- 定时报表订阅；
- 大屏轮播；
- AI 自动归因；
- 复杂审批流；
- 多级系统配置菜单。

MVP 先建立稳定的管理路径、统一页面结构和业务知识入口。真实指标按业务和数据确认进度逐步启用。
