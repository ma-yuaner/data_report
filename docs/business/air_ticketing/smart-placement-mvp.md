- 当前状态：MVP 功能、岗位角色、菜单授权与两级审核流转已实现；真实自动匹配规则待后续接入
- 更新日期：2026-10-10
- 适用范围：智能分析 → 智能投放

## 1. 页面与职责

### 投放政策

路由：`/smart-analysis/placement/policies`

负责投放机会从提出到进入订单监控的完整流转：

```text
分析入池 → 数据经理审核 → 政策经理审核 → 政策员认领
→ 登记投放结果与政策ID → 进入订单匹配监控
```

首版支持任务查询、新建分析机会、两级审核、任务认领、投放成功或失败登记、任务详情和操作时间线。

### 收单情况

路由：`/smart-analysis/placement/orders`

负责查看已投放政策命中的订单，展示票数、航段、预估利润、群消息状态和业务关注状态，并允许登记开始关注、处理完成或无需处理。

订单匹配计算和群消息发送不在本次页面功能内；后续服务写入匹配表后，页面直接展示真实数据。

## 2. 录入字段规则

用户已确认新增分析时不得使用类似“平台/站点”“航司/航程”的合并输入框。以下字段分别填写、分别存储：

- 平台名称、平台编码；
- 站点名称、站点编码；
- 航司；
- 出发地、到达地、完整航程；
- 航程类型、航班号；
- 包含舱位、排除舱位；
- 产品类型；
- 订单日期范围、起飞日期范围；
- 投放方式、调整值、调整单位和建议有效期。

包含舱位与排除舱位均使用英文逗号分隔，提交时不允许同一舱位同时出现在两组条件中。

## 3. 数据表

建表文件：`docs/sql/smart-placement-schema.sql`

| 表 | 用途 |
|---|---|
| `smart_placement_task` | 投放机会、分析条件和当前流程状态 |
| `smart_placement_review` | 数据经理及政策经理审核记录 |
| `smart_placement_execution` | 认领后的投放结果、政策ID和实际执行条件 |
| `smart_placement_order_match` | 政策命中的订单、消息发送及业务关注状态 |
| `smart_placement_operation_log` | 任务和订单关注操作审计日志 |
| `sys_role`、`sys_role_permission`、`sys_user_role` | 智能投放岗位、权限和用户岗位关系 |
| `sys_user_menu` | 账号可见的一级业务菜单 |

新环境执行 `smart-placement-schema.sql` 和 `smart-placement-rbac.sql`；已经创建过智能投放业务表的环境执行 `smart-placement-rbac.sql` 完成岗位表及退回重提字段升级（脚本可重复执行）。应用不会自动创建这些业务表，表未创建时接口返回明确提示，不回退演示数据。

## 4. 当前权限边界

系统管理员在“系统管理 → 账号管理”中为账号分配岗位和菜单。一个账号可以兼任多个岗位：

- `DATA_ENTRY`（数据录入员）：创建、编辑、提交本人投放机会；
- `DATA_MANAGER`（数据运营经理）：只处理待数据审核任务；
- `POLICY_MANAGER`（政策经理）：只处理待政策审核任务；
- `POLICY_OPERATOR`（智能政策员）：查看可认领任务、认领并登记本人投放结果；
- 系统管理员：全量查看和兜底操作，但所有动作仍写操作日志。

任务列表、详情和操作接口均按岗位在后端校验。审核退回后，录入人修改并重新提交：数据审核退回仍回数据审核，政策审核退回直接回政策审核，不重复已经通过的数据审核。

菜单授权与业务岗位相互独立。`sys_user_menu` 控制普通账号可见的一级模块；工作台始终可见，管理员自动拥有全部菜单。例如智能政策员可只分配 `smart` 菜单，只显示智能分析及其智能投放页面。

## 5. 状态定义

任务主状态：

- `DRAFT`：草稿；
- `PENDING_DATA_REVIEW`：待数据经理审核；
- `PENDING_POLICY_REVIEW`：待政策经理审核；
- `CLAIMABLE`：审核完成、等待认领；
- `IN_PROGRESS`：已认领、等待投放或重试；
- `MONITORING`：投放成功、进入订单监控；
- `FAILED`：投放失败且不重试；
- `REJECTED`：审核驳回终止；
- `CLOSED`、`ENDED`：关闭或结束的预留状态。

订单关注状态：`PENDING`、`IN_PROGRESS`、`COMPLETED`、`NO_ACTION`、`ESCALATED`。

## 6. 后续接入项

以下能力仍需业务规则和数据源支持，当前不伪造：

1. 综合分析自动识别投放机会并写入任务池；
2. 根据政策ID和独立条件字段匹配真实订单；
3. 向企业微信群发送来单提醒并回写发送状态；
4. 政策效果复盘、到期提醒和自动结束任务；
5. 如需限制到具体政策小组，再增加任务认领范围的结构化人员/小组规则。
