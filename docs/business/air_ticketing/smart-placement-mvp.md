## 1. 页面与职责

### 投放政策

路由：`/smart-analysis/placement/policies`

负责投放机会从提出到进入订单监控的完整流转：

```text
分析入池 → 数据经理审核 → 政策经理审核 → 政策员认领
→ 登记投放结果与政策ID → 进入订单匹配监控
```

首版支持任务查询、新建分析机会、两级审核、任务认领、投放成功或失败登记、任务详情和操作时间线。

### 收单情况

路由：`/smart-analysis/placement/orders`

负责查看已投放政策命中的订单，展示票数、航段、预估利润、群消息状态和业务关注状态，并允许登记开始关注、处理完成或无需处理。

订单匹配计算和群消息发送不在本次页面功能内；后续服务写入匹配表后，页面直接展示真实数据。

## 2. 录入字段规则

用户已确认新增分析时不得使用类似“平台/站点”“航司/航程”的合并输入框。以下字段分别填写、分别存储：

- 平台名称、平台编码；
- 站点名称、站点编码；
- 航司；
- 出发地、到达地、完整航程；
- 航程类型、航班号；
- 包含舱位、排除舱位；
- 产品类型；
- 订单日期范围、起飞日期范围；
- 投放方式、调整值、调整单位和建议有效期。

包含舱位与排除舱位均使用英文逗号分隔，提交时不允许同一舱位同时出现在两组条件中。

## 3. 数据表

建表文件：`docs/sql/smart-placement-schema.sql`

| 表 | 用途 |
|---|---|
| `smart_placement_task` | 投放机会、分析条件和当前流程状态 |
| `smart_placement_review` | 数据经理及政策经理审核记录 |
| `smart_placement_execution` | 认领后的投放结果、政策ID和实际执行条件 |
| `smart_placement_order_match` | 政策命中的订单、消息发送及业务关注状态 |
| `smart_placement_operation_log` | 任务和订单关注操作审计日志 |

应用不会自动建表。用户需先在 `sibebid` 执行建表文件；表未创建时接口返回明确提示，不回退演示数据。

## 4. 当前权限边界

现有账号只有管理员和普通用户两类角色，尚不能区分数据部经理、政策经理和政策员。因此首版临时规则为：

- 管理员可执行数据经理审核和政策经理审核；
- 已登录用户可创建投放机会；
- 已登录用户可认领可认领状态的任务；
- 认领人或管理员可登记投放结果；
- 已登录用户可更新命中订单的关注状态。

后续新增正式岗位权限后，应将两个审核节点分别授权，不能继续只依赖管理员标记。

## 5. 状态定义

任务主状态：

- `DRAFT`：草稿；
- `PENDING_DATA_REVIEW`：待数据经理审核；
- `PENDING_POLICY_REVIEW`：待政策经理审核；
- `CLAIMABLE`：审核完成、等待认领；
- `IN_PROGRESS`：已认领、等待投放或重试；
- `MONITORING`：投放成功、进入订单监控；
- `FAILED`：投放失败且不重试；
- `REJECTED`：审核驳回终止；
- `CLOSED`、`ENDED`：关闭或结束的预留状态。

订单关注状态：`PENDING`、`IN_PROGRESS`、`COMPLETED`、`NO_ACTION`、`ESCALATED`。

## 6. 后续接入项

以下能力仍需业务规则和数据源支持，当前不伪造：

1. 综合分析自动识别投放机会并写入任务池；
2. 根据政策ID和独立条件字段匹配真实订单；
3. 向企业微信群发送来单提醒并回写发送状态；
4. 正式的数据经理、政策经理、政策员岗位权限；
5. 政策效果复盘、到期提醒和自动结束任务。
