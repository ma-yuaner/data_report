## 执行分工

- 主会话明策：核对仓库DDL/ETL/应用口径，准备指标表、只读SQL；收到结果后核对总量、字段值域、分类冲突和数据限制，形成已确认/待技术确认清单。
- 用户或数据同事：通过现有Hive工具先执行结构查询，确认列存在后运行窄范围聚合，导出结果及实际执行条件；如已有确认可用的只读入口，可另指定由助手取数，本轮尚未核实连接可用性，不假称已查询生产。
- 交易技术：只需补充现有源码不能证明的标识语义：gdsreal值域及代表实际外呼还是意图；日志一行的粒度；apiRequestSubCount含义；traceid/referenceid跨资源/重试的关联规则；别名与资源分类映射。先复用已有字段，不默认要求新增采集。

## 首轮指标定义

| 指标 | 当前定义/状态 | 限制与待确认 |
|---|---|---|
| 日志记录数 | 指定范围内COUNT(*)，与原Excel逐行数对账 | 不自动等于用户请求数或外呼次数 |
| 唯一入口查询数 | 等入口事实和稳定关联键确认后统计 | GDS侧traceid/referenceid只是候选，未确认前不去重冒充入口量 |
| 普通MP实际调用量 | 需确认资源分类和gdsreal等执行证据后计算 | 不能用总量减mpisflag=true推算，余量可能有NDC、NULL和其他记录 |
| MPIS请求标记数/占比 | mpisflag=true记录数/同范围日志记录数 | 标记不等于缓存命中、成功采用或没有MP调用；与接口组交叉核对 |
| NDC实际调用量 | 需结合ndcflag/source_api_group/别名及实际执行证据 | ndccarrierdata非空仅是返回数据条件，不证明完整调用或支持名单 |
| 记录成功/失败量 | 当前DWD仓库定义successflag=0成功、1失败；其余值单列 | 本轮尚未联网核验该版本，接口成功不等于可售结果/被采用 |
| 子接口计数 | apiRequestSubCount聚合单列为候选参考 | ETL将空/0映射成1；不直接等同外呼、计费或用户请求 |
| 缓存命中量/率 | DWD hitcacheflag源码定义0未命中、1 OTA缓存、2 GDS缓存 | 与dws_gds_mpis_interval_day.hit_cache_flag的0无缓存/1被动/2主动不是同一字典，不混用 |
| MPIS实际替代率 | 对确认适用范围、具有可靠关联的请求，核对MPIS成功采用且未发生MP调用 | 请求关联和结果采用数据尚待核对；不能以MPIS标记占比替代 |
| 公司查定比 | 沿用非*_MPIS查询（含NDC）/出票seg_num，MP_TOTAL用于正式比率 | 不改分母、不把API_GROUP航段重复相加；本轮窄范围明细不计算航线查定比 |

“全部”模式的必调MP与明确GDS模式的MPIS回退要分开；这依赖当时生效配置和调用关联。M01先确定如何计数及数据可用性，具体规则匹配和原因归属由M02/M03接续，不在此凭数量差额判因。

## 源码初核结果

1. DWD已有pcc_code、平台站点、旅客、flightWay、traceid/referenceid、mpisflag/ndcflag、gdsreal、缓存/成功等字段定义。需要真实表结构和结果确认，不把源码字段存在等同全部生产数据可用。
2. source_api_group生成顺序：有gdschannelalias时优先别名，否则先判断ndcflag，再判断mpisflag，最后使用gdschannel。因此不能仅用mpisflag将所有记录互斥地分成MP/MPIS。
3. 同时为true、NULL、其他标记或接口组与标记冲突的情况保留为核对项，不强制塞入普通MP。
4. 关联键非空率可以先统计；跨资源一致性、唯一性和重试语义须另核实，不先执行DISTINCT去掉可能合法的多次调用。

证据：ETL仓库`data_pipelines/src/ddl/DWD/dwd_gds_search_carrierdata_5minute.sql`及`data_pipelines/src/dml/分钟任务/ota_gds_minute_ods_to_dws.sh`；应用仓库`backend/data_report_api/services/resource_governance.py`和已有服务表契约。仓库路径不等于线上当前版本。
