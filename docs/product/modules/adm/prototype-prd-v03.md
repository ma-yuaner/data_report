# ADM管理原型与PRD 0.3

更新：2026-10-29。状态：前端可操作原型，供业务直接使用并反馈；不是正式服务端或部署完成。

按用户2026-10-29最新要求，原型必须兼容原数据中台，不独立设计另一套系统。左侧完整保留原系统菜单层级、名称、顺序和预留状态；ADM挂在既有ADM管理下，保留我的工作台和ADM台账。此前六组分类仅作ADM内部页面/窗口评审索引，不是六个新增系统一级菜单；原系统外模块仅展示位置与复用说明，不伪装已制作可操作原型。默认进入ADM我的工作台，未选单据先选ADM；已有业务和意见保留。

左侧为可操作原型，右侧跟随页面/步骤显示功能、逐字段定义、按钮条件和跳转。窗口内同步显示当前动作的前置条件与完成结果。

## 页面与完整办理路径

| 页面 | 功能与去向 |
| --- | --- |
| 我的工作 / 团队督办 | 查看到人任务、期限、交接和协办；点开进入同一张单。组长保留本组督办。 |
| ADM台账 | 搜索、按阶段/平台/下发日期筛选、勾选主单、批量分派/解锁、导出台账或差异交接CSV。 |
| 录入与核实 | 主单与多票号子项、人工确认拆分、本地候选识别、单币种分摊、参考换算、查重、复制、新建预览。预罚可先无订单，转正式补齐。 |
| 单据详情 | 同单切换订单处理、原件附件、结案整改和操作历史；基础信息审核前可编辑并留痕。 |
| 恢复编码 / 申诉跟进 | 集中列表打开原单，记录恢复期限和佐证，或按对象/轮次登记申诉；不另建互不关联的演示。 |
| 审核 / 回款 | 审核通过或退回原承办；审核后按需生成财务待办，支持部分及多次回款。业务结案后继续追踪。 |
| 通知与回执 | 按本人显示、标已读、打开对应任务、登记外部收到回执、生成到期提醒；不对外发送。 |
| 统计与日报 | 当前范围主单/明细、逾期、人员积压排序、原币汇总及可读日报下载；不作为正式绩效考核。 |
| 导入导出 / 历史档案 | 统一CSV模板，先预览后确认，基础更新保留结果与备注；历史约定JSON只读试导、重复源ID跳过、可复制引用。 |
| 规则设置 | 本机维护分派、类型代码、供应默认币种、参考汇率和预警参数。只影响后续新单和匹配，不追溯重派。 |

主流程：录入预览→组长接收/转交→承办接收→同单填写处理意见→申诉或不申诉差异依据→独立审核→协调人整单结案。回款与结案后整改分别继续。审核退回原承办，转交未确认前原人继续负责，期限不重置。

### 录入与主单信息

| 字段 | 含义与用途 | 来源/默认 | 编辑条件 | 必填、校验与影响 |
| --- | --- | --- | --- | --- |
| ADM号 | 供应下发罚单的编号，用于查重和追溯；不是订单号。 | 录入人员按原件填写 | 协调人新建或审核前修改；预罚转正式可补齐 | 正式单必填；同供应商同号禁止重复创建。复制时需改新号。 |
| 来源主体 | 说明由航司、供应商或平台提出罚单。 | 人工选择 | 协调人可改 | 必选；不把邮件、群等通知渠道混入此分类。 |
| 供应商 | 负责下发/对接的供应方，参与查重和负责人预填。 | 原件或供应商配置 | 协调人可改 | 必填；供应默认币种仅预填，用户仍需核对。 |
| 航司代码 | 关联出票/罚单航司，支持后续筛选。 | 原件填写 | 协调人可改 | 正式单必填；不自动认定为责任主体。 |
| 下发日期 | 供应首次下发本单的业务日期。 | 原件日期 | 协调人可改 | 必填；不同于本地创建时间。 |
| 供应回复截止 | 供应要求我司反馈的最后日期。 | 原件要求 | 协调人可改 | 不能早于下发日期；不是实际收到回复的日期。 |
| 具体错误类型 | 罚单事件分类，用于筛选、统计与外部差异代码映射。 | 规则设置中的演示字典 | 录入人/当前承办在审核前可改 | 不等于人为责任认定；正式字典待业务提供。 |
| 预罚核实 | 标记仍在核实阶段，保留预罚记录及转正式历史。 | 人工勾选 | 协调人转换阶段 | 本版无订单可建立核实单；转正式前补齐订单、航司、金额和期限。 |
| ADM内容 | 原罚单的事实、处罚理由和要求，供承办直接阅读。 | 原件摘要或正文 | 协调人在审核前可改 | 必填长文本；与承办分析和内部备注分开。 |
| 主单原币金额 | 供应本张罚单的金额，作为子项分摊核对基准。 | 原件 | 协调人在审核前可改并留痕 | 非负、最多两位小数；正式派发时子项合计必须一致。 |
| 币种 | 本张ADM及所有子项金额使用的币种。 | 供应默认或人工选择 | 协调人新建可改 | 一单一币种；不同币种不直接求和。 |
| 演练参考汇率 | 1单位原币对应多少人民币，用于本地参考换算。 | 本机规则的参考值或手工输入 | 协调人可改 | 正数最多6位小数；缺失显示未换算；本版未连接实时汇率源。 |
| 人民币参考值 | 原币金额×参考汇率的两位小数参考结果。 | 页面计算 | 只读；修改原币或汇率后重算 | 不是应收、实收或财务结算；无汇率不显示为0。 |
| 备注 | 内部补充说明，可用于查询；不覆盖ADM原始内容。 | 录入人员 | 审核前协调人可改 | 可空；批量更新默认保留已有备注，显式确认才覆盖。 |

### 订单与匹配

| 字段 | 含义与用途 | 来源/默认 | 编辑条件 | 必填、校验与影响 |
| --- | --- | --- | --- | --- |
| 订单号 | 我司订单标识，用于核对业务归属。 | 人工录入或本地样例识别 | 审核前协调人核对修改 | 正式明细必填；未匹配不等于非我司，不能自动结案。 |
| 票号 | 本子项关联的客票；一项可以对应多票。 | 原件/订单信息 | 审核前协调人可改 | 无票可空；多票用分号分隔；同单重复票号阻止提交。 |
| 平台 | 对应业务平台，作为任务分派与统计维度。 | 人工确认或本地样例候选 | 审核前可核对 | 必选；识别结果仅是候选，未连接真实订单接口。 |
| 业务 | 本子项属于出票、退票还是改签。 | 原订单核对 | 审核前可改 | 一张主单允许不同业务子项并存。 |
| 子项原币金额 | 本订单承担的主单分摊金额，避免复制整单金额。 | 录入人确认分摊 | 协调人审核前可调，须理由 | 同币种合计须等于主单金额；不自动平均分。 |
| PNR | 预订编码，用于查询和恢复编码核实。 | 订单或人工填写 | 当前承办可补充 | 可空；相同PNR不作为自动归并订单的唯一依据。 |
| 店铺 / 细分站点 | 标记订单经营归属，辅助查询与分派。 | 人工或候选订单信息 | 审核前可修改 | 可空；不因文字相同自动授权整单。 |
| 核实依据 | 说明订单/票号匹配的证据与选择原因。 | 核实人员填写 | 协调人办理时填写 | 匹配提交必填；多候选需人工确认。 |

### 处理意见与差异

| 字段 | 含义与用途 | 来源/默认 | 编辑条件 | 必填、校验与影响 |
| --- | --- | --- | --- | --- |
| 本次处理意见 / 结果 | 当前承办的调查结论及建议，审核人据此复核。 | 当前承办填写 | 办理中和退回后可改；审核通过锁定 | 提交必填；保存草稿可不完整。 |
| 原因归属 | 人为、系统、非人为政策或待认定的原因提案。 | 承办选择并说明 | 审核前可改 | 不自动扣分；个人责任须独立复核。 |
| 处理方式 | 决定进入申诉还是直接说明差异后提交审核。 | 承办选择 | 调查阶段可改 | 申诉→本单申诉记录；不申诉→同页填原因与差异依据后待审核。 |
| 不申诉原因 | 说明为何不再对外提出争议。 | 承办填写 | 不申诉时显示 | 不申诉提交必填，不能以空白表示默认认可。 |
| 需要后续回款 | 审核完成后是否继续生成财务待办。 | 承办提案、审核核对 | 审核前可改 | 勾选需填写应收金额；未勾选须有无需回款依据。 |
| 应收金额 | 本明细预期应退回的原币金额，独立于罚单原金额。 | 申诉结果/财务依据 | 审核前承办填写 | 需要回款时必填且大于0；分次到账累计不得超过应收。 |
| 无需回款依据 | 解释为何无退款或无实际支出。 | 承办填写 | 未勾选回款时可填 | 提交必填；无支出拒单须引用外部确认材料。 |
| 已登记差异 / 差异依据 | 记录外部登记事实、编号或无需登记理由。 | 人工登记回执 | 不申诉或申诉失败后填写 | 必填依据；勾选不代表已调用真实差异系统。 |

## 按钮条件与页面流转

| 操作 | 何时可用 | 点击后结果和去向 |
| --- | --- | --- |
| 新建 / 复制 / 预览确认 | 协调人填写主单与子项；复制不继承旧结果。 | 先显示校验结果，确认后写入本机台账，生成组长接收任务并打开单据。 |
| 接收我的任务 | 当前指定人且待接单。 | 待接单→调查办理；仍在同一张单，可直接填写处理意见。 |
| 提交处理 / 审核 | 本承办调查中，意见、证据、分支依据齐全，无等待/未完恢复/必需协办。 | 申诉→同单申诉；不申诉→差异依据同次保存并交独立审核。失败保留草稿。 |
| 保存草稿 | 本人调查中。 | 保存本单填写内容，不改变办理阶段；有等待事项则保留跟进任务。 |
| 登记一轮申诉 | 本承办、申诉阶段，选择对象、结果和证据。 | 追加本对象轮次，留在本单；可继续登记其他对象或下一轮。 |
| 提交申诉结果 | 每个对象最后一轮均已结束。 | 全成功→待审核；部分成功/失败/撤回→差异登记，填依据后交审核。 |
| 差异登记并提交 | 本承办、差异阶段，登记号或无需登记依据及证据齐全。 | →待审核，保留外部交接依据；没有真实写入差异系统。 |
| 独立审核 / 退回 | 独立审核角色，明细待审核，意见必填。 | 批准→明细完成并按需创建回款；退回→原承办调查中，历史保留。 |

| 取消交接 | 原承办，交接尚未确认。 | 接收人确认待办消失，原承办继续办理。 |
| 核实订单 | 协调人、待匹配，确认订单与平台及证据。 | 按本机规则派发到人，或进入待分派；仍可打开本单继续核对。 |

| 创建协办任务 | 主承办调查中，选择另一位承办、目标及是否必需。 | 新增协办待办；主承办不变，必需协办未完成阻止提交。 |
| 接收协办 | 指定协办人、协办待接收。 | 协办转办理中，仍在原ADM下填写交付物。 |
| 提交协办结果 | 指定协办人办理中，结果及证据齐全。 | 转待独立复核，交主承办或协调人核对。 |
| 复核协办 | 主承办或协调人且不是该协办提交人。 | 批准→协办完成；退回→原协办人继续补充，不直接结束主单。 |
| 提出责任认定 | 主承办调查中，选择原因、涉及人及证据。 | 形成待独立复核提案，不自动罚款、扣分或给责任人额外权限。 |
| 独立复核责任 | 审核角色、提案待复核，须填写依据。 | 记录确认或驳回，历史办理人与当前负责人不随责任结论改变。 |
| 接收整改任务 | 已结案且当前人为指定整改人。 | 整改转办理中，原业务结案保留。 |
| 提交整改验证结果 | 指定整改人办理中，结果与证据齐全。 | 整改转待独立复核，不重写已结案业务快照。 |
| 独立复核整改 | 审核角色、整改待复核。 | 批准→已整改；退回→整改中，原整改人补充。 |
| 挂起主单 | 协调人、未结案未作废，须原因。 | 暂停办理推进并保留记录；不自动免除时限或删除待办事实。 |
| 恢复主单 | 协调人、已挂起，须说明。 | 恢复原办理状态和任务，期限不重置。 |
| 作废并保留档案 | 协调人、未结案，填写作废依据。 | 单据只读并退出活跃待办，历史及附件保留；不物理删除。 |

导航和“切换下一处理人”只更换视图/模拟身份，不替用户提交、审核或结案。操作失败保留弹窗草稿，成功更新任务和留痕；有未保存内容关闭时提示。

## 当前实现边界与待定规则

- 所有状态、权限、通知和金额操作均为本机模拟，不调用正式订单、差异、财务、邮件、企微、GDS或生产数据库。
- 票号/订单识别只从当前本地样例查候选，未命中或多匹配保留人工核对；参考汇率为本地手工值，不是实时接口。
- 本机附件支持图片、PDF、文本预览及其他格式下载，不解析Excel业务内容、不执行ASD自动归档或旧附件迁移。关闭浏览器后的保存依赖本机缓存容量；缓存失败时页面提示导出备份。
- CSV为本版可操作统一模板；外部差异/财务正式模板、旧38/44列、Java/Python真实历史格式映射尚需正式契约。本版历史试导使用原型约定JSON，不冒充全量迁移。
- 节点期限、恢复两天的日历与起点、等待扣时、通知对象/渠道、正式字典/外部代码、财务核对人和附件保留期限仍待业务确认。当前可操作建议不代表这些口径已批准。
- 不实现超时自动拒单、自动删除附件、真实绩效处罚或生产旧入口停用；这些动作需独立确认规则和正式开发。
- 批量改状态仅提供合法的分派/解锁动作，不提供绕过证据、审核或结案条件的任意状态覆盖。
