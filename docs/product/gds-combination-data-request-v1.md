# GDS组合航线治理：数据开发交接单

日期：2026-10-23。业务方：数据部。状态：需求交接，非已建表/已调度/已上线。来源：用户授权现有数据能做的先开发，缺数据部分交数据开发工程师；本轮只交付代码、不发通知、不查生产库。

## 1. 本轮应用先交付什么

复用 `sibebid.bi_gds_resource_metric_day` 的 `MP_TOTAL`，提供GDS＋PCC＋平台＋站点四维组合榜、现有范围筛选/异常筛选、按超额查询量排序、同范围Excel导出、携带四维编码下钻。默认截至昨日完整业务日，手动刷新读取已经落表的最新数据，不宣称小时/分钟实时。上限500项且显式标识截断，不把榜单当全量。

正式分母沿用flag=1出票航段，历史NULL暂兼容为出票；不改变上游ETL。未知/缺失航段不填0、不判超标；现有同步标记并不是全批次完整证明，榜单只用于人工核对。没有航线分母、flag=0指标或换配映射时不虚构数据，不自动关闭配置、不自动发公告。

## D01：组合＋航线日指标

请先提供 `bi_issue_segment_pnr_year` 最新DDL、日期字段定义、航线字段、flag生成逻辑和一组脱敏样例；不要求发送生产连接/密码。

推荐复用现有航线请求日汇总 `lywz.dws_gds_airroute_day`，新增或交付相匹配的航段汇总（表名由数据开发确定，建议不要把高基数航线直接塞进总览服务表）。最终可消费的数据粒度须为：

`业务日期＋GDS编码＋PCC编码＋平台编码＋站点编码＋有方向的标准航线＋flag`

必需内容：

- 四维真实编码，名称可辅助；航线起终点及机场/城市粒度，单程/往返/多段如何映射，正反方向不得混合。查询日志没有真实航司归因时不要补造航司。
- 查询量：普通MP＋NDC；MPIS单列，不进入正式查定比分子。请求原始字段/聚合规则须与现有总览一致。
- 航段量：flag=1、flag=0分别提供 `seg_num`，不得直接相加；请明确是物理航段、承运航段、旅客航段中的哪一种，保持公司现行口径。
- 分别定义查询发生日、预定发生日、出票发生日以及Asia/Shanghai日期；同日流量比不是订单同期转化率，跨日出票需可识别。
- 每侧先汇总到约定粒度再关联，用两侧键并集保留查询独有/航段独有组合；不得将总体航段复制给每条航线或每个API组。

**flag必须先澄清：** A配置预定、B配置出票后，A是否保留flag=0、B另有flag=1，还是原行更新为1？flag=0是全部原始预定还是仅剩未出票？flag=1记录中的PCC是预定PCC还是出票PCC？未明确前，0仅作为“flag=0来源记录”，不能称为全部预定，也不能用0＋1推定唯一预定量。历史NULL另报数量和回填范围，不直接当真实1。

## D02：换配置关联

请提供不含姓名/证件等个人信息的脱敏订单键、PNR关联键及唯一航段键；源系统是否支持此关联需核实，不能从日汇总猜测。

推荐一行表示一个可核验的原预定→出票航段关系，至少包含：

- 原预定四维编码、原预定航线与时间；实际出票四维编码、出票航线与时间。
- 脱敏关联键、唯一关系键、状态及有效性、可归属航段数、源更新时间/版本。
- 同配、换配、未出票、取消/作废、无法关联分别可识别；“无法关联”不等于“未出票”。
- 一个订单多PNR/多航段/重复出票的去重及分配规则；不能一对多关联后把同一出票航段完整分给多条预定记录。未能唯一分配的部分单列，不能强行摊平。

交付后才能新增“本配置预定后在其他配置出票”的可靠贡献指标。原预定贡献是归因指标，不直接替代公司正式出票查定比分母，也不能把它再次加到实际出票量中。

## D03：完整性及重跑

- 按业务日/小时、源类型（查询/flag=0航段/flag=1航段）提供批次ID、状态、统计起止、源水位、源更新时间、服务表更新时间、记录数和基础量对账。
- 明确某组合无行在什么条件下可认定为0；仅当该日有其他组合航段不能证明本组合完整。失败/部分完成须可检测。
- 给出最新可用完整业务日期；重跑幂等、迟到数据回补/修订版本/历史可重算，避免页面仅凭MAX更新时间误认全部同步完成。

## D04：当日观察（非首版前置）

如果需要当日动态观察，提供同四维＋航线＋flag的小时汇总、小时边界、完成状态和延迟水位。刷新频率按源真实更新频率确认，不承诺每5分钟刷新就有新业务数据。当日观察与完整日治理分开，未完成小时/日不得用于直接关闭决定。

## 3. 数据验收示例（均为合成案例，非真实业务数据）

1. A预定、A出票：各口径只有一次合法归属，跨日能追溯。
2. A预定、B出票：保留两个配置的事实和唯一关联，不把A直接判成无业务价值，不重复计全局出票。
3. 同订单多航段、两个PNR、重复同步：累计航段不被关联放大。
4. 有查询无出票、真实零出票、航段同步未完成、无法关联：四种状态明确区分。
5. 多日合计：先合计查询/航段再算比率，不能平均每日比率。
6. 航线分拆后的查询量、出票航段合计能与同日期/同范围四维总览对账；无法归属的余额保留“未知”，不丢弃。

## 5. 四维首版部署配置（应用代码已支持，部署人设置）

沿用 `RESOURCE_GOVERNANCE_GDS_TARGETS=1A:4000`；其他GDS目标由业务提供，例如格式为逗号分隔的 `GDS:正整数`，不默认为4000。

可选 `RESOURCE_GOVERNANCE_COMBINATION_TARGETS`，默认 `[]`，最多100项，完整四维编码匹配优先于GDS默认：

```json
[{"gds":"1A","pcc":"示例PCC","platform":"示例平台编码","site":"示例站点编码","targetRatio":4000}]
```

这只是格式示例，不应原样当生产配置。无目标只显示不判超标；页面目标不是外部合同核定值。环境配置需要重启API，前端构建也需更新；不需要本轮新增数据库表。既有接口增加 `groupBy=combination`，现有鉴权和菜单权限不扩张。
