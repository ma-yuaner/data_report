# 风控亏损原因分类、共享标签与阈值取证 V2

2026-11-05。用户本轮授权需求收集与开发；后续明确所有管理员共享类型和标签。状态：本地实现/隔离验证，实际建表、配置读取与服务器验收分别记录。

## 已确认与原流程

1. `RLA013`是现有“佣金、点击费亏损”合并类型。已有可靠平台编码且不是`QUNAR`时，平台条件优先，直接判为`problem/有问题`；不因出票、佣金、日志缺失降为证据不足。未知/空平台不能推断为非去哪儿，仍证据不足。其他原因不套用此公式。
2. 去哪儿的正佣金、CNY单票、Decimal原精度比较继续保留；本轮不新增独立点击费计算。规则版本为`qunar-commission-loss-config-v5`，旧结果过期，需要用户点击更新并核实才能取得新结论。
3. 中台只核实已有ERP选因，不编辑ERP原原因或交易系统下拉框。页面保留错误选因订单用于取证，不能因其不应选择而隐藏它。若需源ERP选择端强制禁选，属于独立源系统改造，未声称本轮已经实现。
4. 人工发现问题可“＋新增类型→选择1–10项→填写备注→保存标签”。类型与标签管理员共享，记录登记账号ID、时间、原目录快照；不覆盖自动结果，不计入个人抽查通过数，不修改ERP。其他账号原权限不扩大；已有抽查入口保留。

## 通用配置：已确认口径与实现

用户后续明确：新版本止损值取通用配置，不再取订单止损日志。V5自动取证已切换为出票时配置匹配与逐票阈值；配置变更日志只作历史还原证据。查询保持只读，显式更新按钮才发布新的核实结果。

用户提供SQL涉及`base_issue_match_rule`、`base_issue_match_log`、`sibe_ota`、`sibe_ota_site`、`system_com_type_det`。原SQL按昨天日志及近两日规则更新时间过滤，不等于所有有效规则；LEFT JOIN日志后在WHERE限定日志会排除无日志规则，规则与日志/字典可能一对多放大。

新增“读取通用配置候选”显式按钮及只读接口：固定读取RB01、启用、指定两大类的规则ID、平台/站点、起止/更新时间、版本、说明及扩展配置；用EXISTS筛规则大类避免字典关联放大，不关联日志、不保留只看昨天的过滤。最多200项，超限拒绝返回部分规则；单项内容8000字符，截断显式标识。界面明示当前启用候选不等于订单出票时实际命中配置，不参与自动核实。

已核实规则类型、四段JSON字段及原Java匹配排序（条件数量、更新时间、ID依次降序）。当前实现绑定平台、站点、产品、订单来源、航司、出票供应商/GDS及出票方式；PCC仅在两种office字段一致时使用。舱位、地域层级等尚未可靠绑定的条件不忽略，返回证据不足；配置不存在不当0止损。历史范围/状态改变、版本断档或JSON链不连续均拒绝还原，不能据当前匹配条件排除一个历史范围不明的候选。

实读取证：首次只记异常类型而误认为显式配置未就绪，复核安全状态码确认是413候选超过200条，ERP连接实际可用，已向用户更正。增加参数化平台/大类筛选后，只读取得QUNAR及通用范围40条出票盈亏配置，无内容截断；其中37条RB01003002经原字典核实为“出票亏损阈值规则”，另3条RB01003001为“出票盈利阈值规则”，不参与止损识别。原始配置仅留本地忽略目录，未改规则、订单或配置；没有猜地址、回落主MySQL或打印凭据。

37条亏损规则均有可解析的extValue.paramOne/paramTwo/paramThree/paramFour，候选展示对应1/2/3/4段，Decimal字符串保留精度与真实0，缺值/负值/非法值不补0。risk_loss_threshold_config.py负责字段识别及段数计算；具体规则另由历史匹配器选择，不能凭识别成功宣称已命中。候选抽屉显式显示四段字段，盈利规则显示不适用。Java匹配源码先筛有效期/匹配条件，再按非空条件数量降序、update_time降序、ID降序返回，不能只凭规则名或最新一条选阈值。

用户后续确认：段数按每张票；历史订单必须按出票当时配置。2026-11-05进一步确认：超过4段时，阈值＝4段配置＋（单票段数－4）×25元。例如4段配置80元，5段105元，6段130元；1至4段各取对应配置，不累加。新版本不从订单止损日志回退取值。已接入自动取证链路并完成本地定向验证，服务器尚未执行部署。

历史可还原性已继续核实：Java编辑配置路径对比修改前后字段并将扩展JSON差异、配置对象ID及版本/时间写入base_issue_match_log。实库对3条已读规则最多20条日志的只读抽样实际取得7条，确实存在扩展字段修改前后JSON样例；原文仅留本地忽略目录。此证据只证明有可利用的历史变更，不证明所有规则/期间都可重建。必须建立完整版本链、核对配置生效范围及变更时点，断档、直接库改、冲突或无基线则标历史配置无法还原，不拿当前值套旧票。

每次有效核实在既有结果快照记录规则ID/版本、配置JSON与哈希、所选出票时点、票段数、所用阈值及来源。证据哈希包含配置，配置变动后不静默复用旧判定。只读实库取得278条亏损/历史候选，11月1–5日有限抽样10单的历史链无法可靠还原；当天另2单未匹配阈值，均如实证据不足，没有伪造通过。进一步元数据抽样发现多条日志版本号为0，与配置版本不连续，不能据此自动还原。当前仅本地验证，服务器由用户在247执行显式部署与业务验收。

## 数据资产

增加17项ERP/中台核心表元数据登记（包含上述SQL表、票段关联、目录/结果/抽查及两张新表），与原4张经营主表区分；已登记不等于连接可用。扩展7项已在核对中使用的指标和单票配置止损定义，加上原6项，共14项；可展开用途、来源、粒度、单位、去重、NULL、更新时间口径和权限。原6项仅补已知来源及元数据，源唯一键、币种覆盖、NULL及同步细节未独立核验的明确写待核验，不改其既有公式。没有伪造表行数、阈值、财务公式或新指标实绩。

单票配置止损值定义：用途为RLA013单票选因核对；公式见上述1–4段/超过4段口径；来源为base_issue_match_rule.ext_json与票段关联；粒度为出票明细ID；时间为issue_ticket_time时有效配置；单位元/CNY；按有效航空航段ID计数并检查关联行数一致，重复或缺关联不计算；NULL不补0；更新时间为显式更新并核实的成功批次；权限为现有管理员，自动结果按账号隔离。
