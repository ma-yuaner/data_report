# 产品方案与交付规范

更新：2026-10-20。适用于企业数据中台新增页面、分析与流程需求；这是后续工作的设计约定，不代表组件和功能已全部开发。

## 1. 先说清业务问题

每项需求写明：谁在什么场景遇到什么问题、要据此做什么决定、成功如何衡量、当前有哪些数据。用一个真实业务例子定义输入、输出和操作结果。能复用总览、下钻、监控中心、通知或工单的，优先复用。

方案状态使用：草案 → 业务确认 → 设计就绪 → 开发中 → 待部署/数据 → 待验收 → 已验收。用户已经授权的范围不重复确认；缺少的业务决定单列，不冒充默认值。

## 2. 每个需求的交付清单

| 设计内容 | 最小必要信息 |
|---|---|
| 数据 | 源表、目标表、粒度、唯一键、更新时间、完成标记、保留期、负责人 |
| 指标 | 公式、分子/分母范围、去重、NULL/0、时间归属、汇总方式、版本 |
| 筛选/下钻 | 支持的字段、继承条件、编码与名称映射、粒度不兼容的处理 |
| API | 实际路由、参数类型/必填、范围限制、响应字段、分页、权限、错误/空态 |
| 流程 | 谁可以做什么、允许的起止状态、重复提交、取消、失败/超时/恢复路径 |
| 数据库/ETL | 已有表复用、新增理由、迁移/回补、调度依赖、重跑与回退 |
| 通知 | 事件触发点、收件人与群、模板字段、幂等、重试、发送日志 |
| 验收 | 正常、无数据、部分同步、重复执行、越权、失败回传和恢复的证据 |
| 交接 | SQL由谁执行、技术消费哪些字段、调度顺序、部署和验收结果 |

## 3. 页面与组件约定

| 组件/场景 | 产品约定 | 现有参考 |
|---|---|---|
| 筛选 | 日期和范围有可见标签；明确即时/手动查询；昂贵查询手动触发，保留查询快照 | `frontend/src/components/FilterPanel.vue` |
| 指标卡 | 主指标突出，辅助量放副标题；同时有单位、期间与质量状态；NULL不写0 | 资源治理、综合分析现有页 |
| 维度对比 | 粒度、排序、分页/截断说明明确；比例按分子分母重算 | `ResourceGovernanceView.vue` |
| 分析此项 | 右侧工作区承接，保留期间和全部适用条件；返回不丢上下文 | 资源治理与综合分析既有交互 |
| 详情/表单 | 标签在输入框外；一字段一控件；日期真实可选；必填与错误就近显示 | 基于项目已有组件评审，不另起一套样式 |
| 流程操作 | 只显示当前角色/状态可做的动作；禁用需说明原因；成功后更新详情和日志 | 监控中心事件/工单 |
| 慢查询 | 加载时展示范围、等待说明、禁止重复提交；失败可重试，旧结果不冒充新范围 | Hive航线页，30–60秒为估计 |
| 空态 | 未查询、查询为0、未同步、无权限、查询失败分别解释 | 不统一显示“No data” |
| 演示 | 标签明确“演示”；与真实事件/工单入口分清；不拿模拟状态做效果证明 | `GdsRouteGovernanceView.vue` |

未来若抽公共组件，先核对相同行为在多页面重复出现；单页需求不为“通用”预先做复杂配置引擎。

## 4. 发布与文档

代码实现、数据库迁移、数据同步、ETL调度、服务器部署、业务验收分别记录。后端必须执行权限和状态检查，前端隐藏按钮不能代替授权。

完成后更新相关业务契约及`docs/agent/workstreams.md`；重要决策写入`decisions.md`，稳定背景才进入`memory.md`。按根AGENTS.md执行适当检查与推送；纯文档不连接数据库、不触发通知、不重跑ETL。
