# 产品方案与交付规范

更新：2026-10-27。适用于企业数据中台新增页面、分析与流程需求；这是后续工作的设计约定，不代表组件和功能已全部开发。

## 0. 用户先审的原型交付模式

### 调用名：需求先行·原型评审模式

2026-10-27用户要求为该工作方式固定名称，并强调制作前先了解清楚需求文档。调用示例：“按需求先行·原型评审模式做XX，先读这些需求资料。”本项目中提到该名称即按以下步骤执行；其他项目需提供此约定或对应文档，不声称跨项目自动记忆。

1. **先读需求**：定位并阅读用户提供的需求文档、相关已确认决策和已有功能说明。缺失或打不开的资料明确列出，不能凭旧原型代替需求理解。
2. **对齐理解**：简要列出目标、角色、日常任务、输入输出、字段用途、权限、正常/异常流转及验收标准；区分已确认、待确认、产品建议、暂不实施，并保留来源。影响主流程的缺口先澄清，不擅自固化；非阻塞假设可显著标注后用于演示。
3. **复用优先**：先查现有组件和业务能力，只改差异。评审外壳复用 `frontend/prototypes/shared/README.md` 所列入口；业务组件按实际契约复用，不重新生成整个原型或通用引擎。
4. **原型与PRD联动**：HTML左侧模拟系统、右侧当前页面PRD；需求、页面、规则和验收项按稳定编号关联。原型用于检验需求，不能反向将模拟规则当作已确认需求。
5. **意见与复验**：用户操作和提意见，按受影响编号局部修改，并给出改动点、体验入口及待确认项，不重复输出整份背景或无变化文档。
6. **批准后交开发**：用户明确批准具体版本与范围后才进入正式业务开发；复用组件的技术整理不代表业务需求获批。继续遵守下述生产与批准边界。

用户2026-10-27确认ADM采用场景驱动产品验收台：业务全景＋可重置场景演练＋联动PRD＋版本化意见/验收。具体执行见[明策v6](../agent/roles/product.md#v6场景驱动产品验收台与开发关口优先适用)。复杂新模块/流程重构默认提议采用，小修复仍可裁剪；用户要求先审时，本节优先于下文直接开发简化规则。

原型优先复用Vue/TypeScript及现有公共组件，在隔离入口用合成数据和显式状态流演示，不接生产接口。菜单/角色/任务流、页面、字段及分析用途、权限、状态变化、异常与验收以稳定ID关联；左原型右说明、可拆窗口，业务人员可写意见并导出记录。多人意见需要共享存储/身份/版本控制，不能靠各自浏览器缓存声称协同。技术选型由实现角色复核，不建设过度通用的流程引擎。

用户明确批准具体版本/范围后才交正式业务开发；沉默、AI自检和演示不算批准，原型制作授权也不等于业务实现授权。交接需带批准证据、覆盖清单、规则/权限/字段基线、复用与改造项、依赖和未决项。后续修改写明影响及定向重验范围；批准不包含DDL、生产切换、部署或真实通知。规范生效不代表ADM原型已完成。

## 1. 先说清业务问题

每项需求写明：谁在什么场景遇到什么问题、要据此做什么决定、成功如何衡量、当前有哪些数据。用一个真实业务例子定义输入、输出和操作结果。能复用总览、下钻、监控中心、通知或工单的，优先复用。

方案状态使用：草案 → 业务确认 → 设计就绪 → 开发中 → 待部署/数据 → 待验收 → 已验收。用户已经授权的范围不重复确认；缺少的业务决定单列，不冒充默认值。

## 2. 可选交付清单（按紧急程度、难度与风险裁剪）

按用户2026-10-20最新要求，先看紧急程度和难度，难任务也不强制走完整流程；范围与授权明确时可直接开发，下面表格只取本次必需项，不要求八项方案或全部角色打卡。验证只覆盖直接相关风险，不默认复杂测试或全量回归；新test文件/临时验收产物不上传Git，已有正式测试库不批量删除。裁剪不扩大开发、数据库或生产权限。

| 设计内容 | 最小必要信息 |
|---|---|
| 数据 | 源表、目标表、粒度、唯一键、更新时间、完成标记、保留期、负责人 |
| 指标 | 公式、分子/分母范围、去重、NULL/0、时间归属、汇总方式、版本 |
| 筛选/下钻 | 支持的字段、继承条件、编码与名称映射、粒度不兼容的处理 |
| API | 实际路由、参数类型/必填、范围限制、响应字段、分页、权限、错误/空态 |
| 流程 | 谁可以做什么、允许的起止状态、重复提交、取消、失败/超时/恢复路径 |
| 数据库/ETL | 已有表复用、新增理由、迁移/回补、调度依赖、重跑与回退 |
| 通知 | 事件触发点、收件人与群、模板字段、幂等、重试、发送日志 |
| 验收 | 正常、无数据、部分同步、重复执行、越权、失败回传和恢复的证据 |
| 交接 | SQL由谁执行、技术消费哪些字段、调度顺序、部署和验收结果 |

## 3. 页面与组件约定

视觉、表格、窗口、内网HTTP兼容和交互验收遵循[统一规范](ui-consistency-standard.md)。新增/修改复用固定骨架和相邻组件，不每次另起风格；不代表旧页已全部符合。

| 组件/场景 | 产品约定 | 现有参考 |
|---|---|---|
| 筛选 | 日期和范围有可见标签；明确即时/手动查询；昂贵查询手动触发，保留查询快照 | `frontend/src/components/FilterPanel.vue` |
| 指标卡 | 主指标突出，辅助量放副标题；同时有单位、期间与质量状态；NULL不写0 | 资源治理、综合分析现有页 |
| 维度对比 | 粒度、排序、分页/截断说明明确；比例按分子分母重算 | `ResourceGovernanceView.vue` |
| 分析此项 | 右侧工作区承接，保留期间和全部适用条件；返回不丢上下文 | 资源治理与综合分析既有交互 |
| 详情/表单 | 标签在输入框外；一字段一控件；日期真实可选；必填与错误就近显示 | 基于项目已有组件评审，不另起一套样式 |
| 流程操作 | 只显示当前角色/状态可做的动作；禁用需说明原因；成功后更新详情和日志 | 监控中心事件/工单 |
| 慢查询 | 加载时展示范围、等待说明、禁止重复提交；失败可重试，旧结果不冒充新范围 | Hive航线页，30–60秒为估计 |
| 空态 | 未查询、查询为0、未同步、无权限、查询失败分别解释 | 不统一显示“No data” |
| 演示 | 标签明确“演示”；与真实事件/工单入口分清；不拿模拟状态做效果证明 | `GdsRouteGovernanceView.vue` |

未来若抽公共组件，先核对相同行为在多页面重复出现；单页需求不为“通用”预先做复杂配置引擎。

## 4. 发布与文档

代码实现、数据库迁移、数据同步、ETL调度、服务器部署、业务验收分别记录。后端必须执行权限和状态检查，前端隐藏按钮不能代替授权。

完成后更新相关业务契约及`docs/agent/workstreams.md`；重要决策写入`decisions.md`，稳定背景才进入`memory.md`。按根AGENTS.md执行适当检查与推送；纯文档不连接数据库、不触发通知、不重跑ETL。
