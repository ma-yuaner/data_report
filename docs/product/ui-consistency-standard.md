# 企业数据中台页面与交互统一规范

版本：v1。2026-10-24。来源：用户要求蒸馏既有使用习惯，后续开发保持一致。
适用data_report新增/修改页面、表格、弹窗及接口反馈；不代表旧页面已经全部改造或验收。

## 1. 固定原则与边界

- 用户反复确认：简洁实用、少步骤、表格整齐、长内容可展开、操作就地完成、滚动可达、保存有反馈、刷新不抽动不置顶；页面和新建窗口不能每次另造风格。
- 中台以现有Vue/Ant Design Vue及`frontend/src/styles/main.css`为基线：浅灰内容背景、白色内容区、蓝色主操作、深色正文，保留现有导航。
- 参考AI产品简洁的信息层级，不把聊天布局推广到台账、ADM、财务和分析页，不自动隐藏业务导航。
- data_need的15行分页、聊天气泡、绿色最终闭环开关及吴泽展权限是模块规则，不推广全站。不能通过按钮外观改变业务权限。
- 优先级：用户本次明确要求 > 已确认业务/权限契约 > 本规范 > 局部样式偏好；有冲突先指出。

## 2. 视觉与骨架

以下数值是本次统一默认值，不是所有旧页面已实现的事实。已有相邻页面/共享组件有稳定规格时优先复用，例外只记录差异。

| 项目 | 默认规范 |
|---|---|
| 页面 | 标题及主要操作 → 筛选 → 内容/表格 → 分页；复用PageHeader、FilterPanel等现有组件 |
| 配色 | 沿用背景`#f2f5f9`、主操作蓝、正文`#182235`；状态同时配文字 |
| 间距 | 8px节奏；同组8–12px，区块16–24px；桌面内边距沿用24px |
| 字体 | 正文/表单默认14px，辅助12–13px；标题沿用PageHeader，不随页缩小字体 |
| 控件 | 编辑/查询默认AntD middle；密集表格可small，同区域一致 |
| 装饰 | 薄边界、克制圆角/阴影，业务内容不新增大渐变、玻璃装饰和巨型说明卡 |
| 操作 | 同区域一个主操作；次要弱化，危险操作单独确认；文字短、直接 |
| 空态 | 未查询、无数据、未同步、无权限、失败分别说明；NULL不冒充0 |

不为统一风格引入新框架、依赖、图片或复杂配置引擎；不逐页复制整套CSS。

## 3. 表格与筛选

- 同表行高一致；正文最多两行，长文点击浮层/抽屉看全文并可复制，不能只支持hover。编辑/导出使用原始全文，不保存省略文本。
- 名称可换行，标题和描述不重复堆叠；按状态、日期、人员、长文设置不同列宽，不全部等宽。金额/数量右对齐、等宽数字，标明单位和币种，不用前端重算正式财务合计。
- 高频字段按授权原位编辑，复杂联动进详情。保存中防重复，成功才更新，失败保草稿并给原因；后端仍鉴权和校验版本。
- 中文composition期间不得重建输入框、变key、抢焦点或刷新覆盖输入；明确即时/手动查询，昂贵查询手动触发。
- 管理台账默认最新提报/创建时间降序、稳定ID次排序；指标排行与流程历史按业务约定，不机械套日期。
- 大列表服务端分页，页码/总数可见，每页数量沿用模块，不把知序15行强制全站；导出与筛选/查询快照一致。
- 宽表只在数据区横滚，横向滚动条在当前视口可到达，不要求先拉到底部；优先组件sticky/滚动能力，不无故增加假滚动条。固定列、表头、合计不得错位。

## 4. 新建与编辑窗口

- 点击新建立即打开本地表单；选项异步加载在窗口内展示，不能等接口时无反馈。权限/前置失败给明确原因。
- 简单表单优先弹窗；复杂阅读用抽屉或已有详情页，沿用相邻模块。
- 默认宽720–800px，复杂导入预览900–1000px；窄屏不超视口减32px。内容区受视口高度约束，标题和保存/取消可达，不溢出屏幕。
- 标题写清“新建/编辑＋对象”；按真实业务分基本信息、明细、附件，省略无用空区块。
- 标签在输入框外，必填、格式示例和错误就近显示；桌面简单字段两列、长文整行、小屏一列。日期/人员复用既有组件。
- 多明细在底部“＋添加……”独立编辑/移除，不继承旧完成状态、不自动平分金额或填造事实；附件须先保存时提示下一步。
- 保存链：基本校验 → 禁重复 → 服务端校验 → 成功反馈并同步列表/详情；失败保留输入不关窗、不先报成功。版本冲突提示核对，网络未知结果先查后重试。
- 一份新建草稿仅生成一次幂等键，失败重试沿用，另开新单才换键；导入先预览再确认，错误不能跳过。
- 有未保存编辑时关闭需确认；防遮罩误关，关闭恢复背景滚动和焦点，不遗留锁屏。

## 5. HTTP兼容与稳定反馈

- 普通内网HTTP是实际部署场景，禁止无保护依赖`crypto.randomUUID`等安全上下文专用能力。ADM复用`features/adm/identifier.ts`；跨领域复用先确认契约再提取，不复制错误实现。
- 点击、保存、导入、导出必须有可见结果/错误；不能只记console、吞异常、把失败显示完成。给用户下一步、安全诊断码，不泄露凭据或SQL。
- 同范围刷新局部更新，保留焦点、中文输入、滚动、列宽和选中；旧请求不能覆盖新条件，离页清理轮询。
- 仅实际后台作业需要轮询，复用既有频率/退避，隐藏页面暂停或降频；普通台账不新增无意义高频刷新。
- 作业显示排队/执行/成功/失败及原因，取消/超时以服务端为准；不伪造进度，不无限付费重试。
- 导出复用全站导出任务、筛选与权限，不独立再造流程，不把预览冒充全量。

## 6. 后续开发与验收

1. 主代理先读本规范和本次相关组件/角色，选现有相邻页，短说明复用入口与差异，不重复整套设计。
2. 绘景交接差异，星桥实现，磐石守接口/幂等/权限，明鉴按风险补验；不机械启动子代理或跑全量测试。
3. 多页确有相同行为才提取共享组件；不因规范批量重写旧页，触及哪页修本次相关项。
4. 必验本次主路径：点击入口 → 填写 → 保存 → 刷新仍存在；补相关失败、权限、中文、长文、重复点击。金额/写库/删除保留安全检查。
5. 窗口/表格实际浏览器检查1440/1280/1024宽度、低高度及125%/150%缩放影响点；HTTP测真实兼容。受限明确“未验”，静态检查不等于点击跑通。
6. 交付区分实现、验证、部署、人工验收；临时测试/数据不入Git，不宣称全站已经一致。

最小清单：风格一致；长文/金额/空值不溢出；中文输入稳定；滚动及弹窗按钮可达；失败保草稿；HTTP入口可用；权限/幂等正确；未验项明确。
