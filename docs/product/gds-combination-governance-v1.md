## 已确认规则

- 目标：判断哪个GDS＋PCC＋平台＋站点组合查定比高，精准通知处理，不因局部超标关闭整个GDS、PCC或平台。
- 各GDS独立默认阈值，1A整体4000:1，其他GDS值待配置，不共用4000。
- 组合专属阈值优先于所属GDS默认；未设置则继承默认，两者均无只展示不判超标。组合阈值不改变整体考核标准；页面展示生效阈值及来源。
- 关闭精准到四维组合；通知/执行记录使用真实编码，名称辅助展示。缺关键编码不能生成精准关闭指令，不能自动扩大作用范围。

## 指标与安全边界

组合查定比＝同期间同组合非MPIS查询量合计／出票seg_num合计；包含NDC，不用PNR、票数或生单成功数代替。多天按基础量合计重算，不平均日比率。使用MP_TOTAL，不混入无独立航段分母的API_GROUP。沿用flag=1出票、历史NULL兼容，flag=0订位单独分析；首版用昨日及以前完整日，不用今日未完成数据决定关闭。

- 未同步/部分同步不能当0；现有ETL“当日有任意航段即将细分缺行视为0”只是兼容策略，关闭前须核验批次、覆盖和组合归属。
- 完整且查询>0、航段=0可显示∞，但不因此自动关闭。查询与出票PCC可能不同，无本组合出票不能直接证明无业务价值。
- 超额查询量=max(查询量－生效阈值×航段数,0)，只作相对阈值的优先级参考，不等于已证实无效查询。

## 最小方案

复用现有GDS资源治理及监控中心，保留单维总览/下钻，增加组合明细榜、组合趋势和携带完整范围的处理通知，不另建复杂系统。

每行字段：GDS、PCC、平台、站点、查询量、出票航段数、查定比、生效阈值、阈值来源、超额查询量、数据质量、查看趋势/通知处理。各维度可筛选，建议按超额查询量结合查询规模看优先级，不只按∞或最高比率排序；明确分页/统计范围，不能将现有Top500当全量。

流程：组合超标 → 人工核对 → 确认关闭该组合 → 通知执行人 → 回填实际生效结果 → 同范围完整日效果观察。只标“超标待处理”，不直接标“必须关闭”；不自动执行关闭。通知带真实编码/名称、期间、基础量、比率、阈值及来源、拟调整范围。通知成功不等于关闭成功，须有执行结果和实际生效时间。
