# 本地账号登录 V1 需求

来源：用户于 2026-10-08 将登录立项范围收敛为本地账号登录，明确取消企业微信接入和部门数据权限；部门等归属信息未来通过元数据标签治理，不为本次登录改造现有源数据。

状态：需求已确认并进入开发。用户于2026-10-08确认闲置超时4小时、单次登录最长24小时。

## 1. 建设目标

为企业数据中心增加简单、可靠的本地账号登录能力：

1. 未登录用户不能进入数据中心或调用业务 API；
2. 账号由系统管理员统一创建、启用、禁用和重置密码，不开放自主注册；
3. 用户使用用户名和密码登录；
4. 登录成功后使用有时效的服务端会话；
5. 长时间没有操作时会话自动失效，再次访问必须重新登录；
6. 用户可以主动退出，管理员禁用账号后旧会话立即失效；
7. 登录成功、失败、退出和账号管理操作可审计。

V1 只解决“谁可以进入系统”，不按部门、平台、公司或人员区分业务数据范围。所有已启用的普通账号暂时看到相同业务数据。

## 2. V1 角色

| 角色 | 能力 |
|---|---|
| 系统管理员 | 创建账号、重置密码、启用/禁用账号、查看登录审计；同时可使用现有业务页面 |
| 普通用户 | 登录、修改本人密码、退出登录、使用现有业务页面 |

V1 不建设自定义角色、菜单权限、数据权限和审批流。管理员身份只用于账号管理。

## 3. 登录流程

1. 用户访问任意业务页面；
2. 系统发现没有有效会话，跳转 `/login` 并记录原访问地址；
3. 用户输入用户名和密码；
4. 后端检查账号是否存在、是否启用、是否被临时锁定，并验证密码；
5. 验证成功后，后端创建随机会话并通过安全 Cookie 返回浏览器；
6. 用户回到原访问页面；
7. 验证失败时统一提示“用户名或密码错误”，不泄露账号是否存在；
8. 会话过期后，下一次页面访问或 API 请求统一跳回登录页。

## 4. 账号管理

- 账号只能由系统管理员创建，不允许用户自主注册；
- 用户名必须唯一，建议使用工号、姓名拼音或公司统一账号；
- 创建账号时设置一次性初始密码；
- 用户第一次登录后必须修改初始密码；
- 管理员可以重置密码，重置后旧会话全部失效；
- 管理员可以禁用账号，禁用后不能继续登录，已有会话立即失效；
- 不删除已有审计记录；离职账号采用禁用，不直接物理删除；
- V1 不建设“忘记密码”邮件或短信流程，由管理员执行重置。

## 5. 密码与简单验证

建议默认规则：

- 密码至少8位，必须包含字母和数字；
- 初始密码首次登录必须修改；
- 密码只保存安全哈希，禁止明文、可逆加密或写入日志；
- 使用 Flask/Werkzeug 提供的 scrypt 密码哈希，不保存明文或可逆密文；
- 连续5次登录失败后锁定15分钟，降低暴力尝试风险；
- 登录接口增加基础频率限制；
- 不增加短信验证码、图形验证码和双因素认证，保持第一版简单。

## 6. 会话与 Token 时效

V1 使用后端保存的随机会话 ID，不在浏览器 `localStorage` 保存可伪造角色或长期 JWT。

已确认默认值：

| 项目 | 建议值 | 规则 |
|---|---:|---|
| 无操作超时 | 4小时 | 4小时没有有效 API 活动，会话失效并要求重新登录 |
| 单次登录最长时间 | 24小时 | 即使持续操作，达到上限后仍需重新登录 |
| 活动续期 | 开启 | 有效操作刷新最后活动时间，但不突破24小时绝对上限 |
| Cookie | `HttpOnly + SameSite=Lax` | JavaScript不可读取；正式HTTPS环境增加`Secure` |
| 主动退出 | 立即失效 | 服务端删除会话，浏览器清除Cookie |
| 密码重置/账号禁用 | 全部会话失效 | 防止旧浏览器继续访问 |

会话失效时 API 返回401和统一错误码，前端提示“登录已过期，请重新登录”，跳转登录页并保留原访问地址。

## 7. 页面与接口范围

### 7.1 前端

- `/login`：用户名、密码、登录按钮和失败提示；
- 首次登录修改密码页；
- 全局路由守卫：未登录不能进入业务页面；
- 全局401处理：会话过期统一返回登录页；
- 顶部用户区域：显示真实用户名，提供修改密码和退出登录；
- 账号管理页：仅管理员可进入，支持新增、重置、启用和禁用。

### 7.2 后端

建议接口：

- `POST /api/auth/login`：验证本地账号并创建会话；
- `GET /api/auth/me`：返回当前用户及是否管理员；
- `POST /api/auth/logout`：销毁当前会话；
- `POST /api/auth/change-password`：修改本人密码；
- `/api/admin/users`：管理员创建、启用、禁用和重置账号；
- 除 `/api/health` 和登录接口外，现有 API 全部要求有效会话。

## 8. 数据结构

V1 至少需要：

- `auth_user`：用户名、姓名、密码哈希、管理员标记、启用状态、首次改密标记、失败次数、锁定时间、密码更新时间；
- `auth_session`：随机会话哈希、用户、创建时间、最后活动时间、绝对失效时间、撤销时间；
- `auth_audit_log`：登录成功/失败、退出、改密、创建账号、重置密码、启用和禁用。

建议将认证表建立在独立认证库或当前MySQL独立表前缀下，不写入Hive。数据库密码和应用Secret继续保存在部署环境变量中，不提交到Git。
本版本不修改或复用原系统已有的 `sys_user`、`sys_user_menu`，避免耦合原密码算法和菜单权限模型。

## 9. 数据权限与元数据边界

- V1 不读取用户部门，也不按部门过滤任何页面或 API；
- 本次登录开发不修改 `bi_business_profit_dimension_day` 或其他业务表结构；
- 部门、平台、业务域等归属信息未来在数据资产中以元数据标签、数据集负责人和可见级别进行治理；
- 元数据标签可以控制整个数据集或页面是否可见，但不能在没有组织字段的情况下实现同一张表内部的部门行级隔离；
- 如果以后重新提出“不同部门看同一张表中的不同记录”，必须由源数据提供稳定的组织关联，不能根据中文名称或前端标签猜测。

## 10. 安全要求

1. 所有业务 API 在后端统一校验会话，不能只靠前端路由；
2. 登录接口使用参数化查询和统一失败提示；
3. 密码、完整会话ID和数据库凭据不能进入日志；
4. 回跳地址只能是系统站内路径，禁止开放重定向；
5. 正式环境推荐HTTPS；HTTP只用于受控测试环境；
6. 管理员接口必须再次校验管理员身份；
7. 会话Cookie设置 `HttpOnly` 和 `SameSite=Lax`，HTTPS环境设置 `Secure`；
8. 登录、改密和账号管理接口增加CSRF防护或同源校验；
9. 应用启动时禁止继续使用默认生产 `SECRET_KEY`。

## 11. V1 验收标准

1. 未登录访问业务页面会跳转登录页，直接请求业务API返回401；
2. 正确账号密码可以登录并返回原访问页面；
3. 错误密码、禁用账号和锁定账号不能登录；
4. 首次登录必须修改初始密码；
5. 普通用户不能进入账号管理页，也不能直接调用管理员API；
6. 管理员可以创建、禁用、启用和重置账号；
7. 闲置达到确认时长后必须重新登录；
8. 达到绝对会话时长后即使持续操作也必须重新登录；
9. 主动退出、密码重置或账号禁用后，旧会话不能继续调用API；
10. 登录成功/失败、退出、改密和账号管理操作都有审计记录；
11. 所有已启用普通用户看到相同业务数据，不应用未确认的部门过滤；
12. 密码和会话凭据不会以明文进入数据库、浏览器存储、日志或Git仓库。

## 12. V1 不包含

- 企业微信、LDAP、AD或其他单点登录；
- 部门、公司、平台等数据范围控制；
- 自定义角色和菜单权限；
- 自助注册和短信/邮件找回密码；
- 图形验证码、短信验证码和双因素认证；
- 复杂账号审批；
- 根据源业务数据自动判断用户部门。

## 13. 已确认实施参数

1. 闲置4小时失效，单次登录最长24小时；
2. 密码至少8位且包含字母和数字；
3. 连续5次失败锁定15分钟；
4. 认证表放在现有`sibebid`并使用`auth_`前缀；
5. 首个管理员通过部署环境变量一次性初始化，密码不提交到Git；
6. 当前HTTP测试环境关闭Secure Cookie，切换HTTPS时通过环境变量开启。
