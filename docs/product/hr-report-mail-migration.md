## 已核对的业务规则

- 部门映射按原函数读取活动Sheet的前四列：部门、负责人、邮箱、抄送；保留原匹配规则，不改模糊匹配/默认收件人。缺少邮箱标无效且不得发送。
- 周报周期按原文件名两段8位日期提取，不用上传日期替代。`AttendanceParser`保留异常排行榜、概况统计与打卡明细、弹性班次踩点关注名单的现有读取/排序/筛选，正文用`build_email_html/get_email_subject`，附件用`generate_dept_attachment`。
- 周报原附件保留排行榜及未专门处理的Sheet；概况和弹性名单按部门过滤。不能把“等价迁移”误写为所有Sheet都过滤，额外Sheet存在时需显式核对数据暴露范围。
- 月报四Sheet：考勤总览、考勤异常人员明细、请假明细、出差或外出明细；部门来自四表并集。总览B姓名/C部门/G异常合计/W旷工/X迟到/Y早退/Z补卡/AA缺卡/AB扣罚。
- 月报正文`get_person_exceptions`只取异常合计>0、按异常降序及姓名次排序；`_safe_int_or_text`保留非空非数字文本，不转0。原有数值整数转换规则保持，不擅改精度。
- 月报邮件用`build_monthly_email_html/get_monthly_email_subject`；附件总览保留本部门全部人员，不仅正文异常人员，其他三Sheet按部门原始行写入、空Sheet删除，沿用原函数。原函数保留额外非目标Sheet，需与旧系统逐Sheet对照。
- 邮件生成含当前时间页脚；对照时冻结同一业务时钟，发送用用户确认过的同一主题/HTML快照，避免重新生成造成预览与发送不一致。
- SMTP与企微邮件API两条通道保留，不能把群机器人Webhook当邮件API。原批量发送逐封结果须迁成数据库记录，不能仅保存最后的总数或console输出。

## 迁移实现边界

| 原功能 | 中台承接目标 |
|---|---|
| main_window上传/类型选择 | 周/月报与映射分别上传，显式选择本次类型；改文件后旧预览失效 |
| 部门表/勾选 | 全选/取消全选/仅有效，缺邮箱不允许进入发送清单 |
| 逐部门预览/最终确认 | 收抄送、主题、完整HTML、附件可核查；服务端确认版本和实际清单 |
| 解析/正文/图表 | 尽量复用原函数，隔离桌面依赖，不复制配置凭据 |
| 临时附件 | 私有平台文件区，批次/部门独立目录、防碰名/越权；预览与发送附件hash一致 |
| SendWorker/发送日志 | 持久发送批次与逐封状态/操作人/周期/收抄送/安全错误，刷新可查 |
| 本地JSON日志 | 新记录数据库审计，旧JSON历史另作显式导入，不假称已迁完 |
| SMTP界面/settings | 平台密钥引用；前端/业务数据库不收取明文密码、不回显、不入日志 |

发送确认必须绑定冻结清单、内容和附件；原子领取避免双击/多进程重复发送。邮件服务端接受不等于最终投递成功；网络中断或发送后进程崩溃需标结果未知、人工核实，不盲目自动重发。批次可部分失败，不把失败或缺附件冒充成功。
