# 数据加工工作台易用性 V2

2026-10-26。用户授权补齐删除、计算列/特征工程、关联诊断和金额精度；代码交付不等于部署或真实财务验收。不读取生产库或改动用户Excel。本轮复用原数据集/流程/任务/worker及公共FormDialog，无新增运行依赖或独立计算服务。

## 使用与本轮范围

1. 导入两表后先把参与数学计算的字段转换为精确数值，小数位可选0–12。原表仍为文本保留；减少小数位采用四舍五入，检查报告显示变化数量及最多10条来源行号/原值/结果样例。已按6位转换的结果改成9位不能恢复，须修改上游转换步骤并重新运行。
2. 顶部“新增计算列”→选择“多个字段求和”→多选三个及以上数值字段→填写结果名称/小数位→加入步骤→预览→全量运行。也可选择受控表达式，点字段按钮插入稳定ID，支持括号、加减乘除和下列函数。页面不用JavaScript计算正式金额。
3. 用户举例“应付原币金额(业务流)+实付原币金额(资金流)+应付CNY金额(业务流)”可按明确指令执行，但混合币种/业务流与资金流不自动等于合理财务指标，不自动换汇。界面固定提醒，原币与CNY/本币同时参与时报告额外警告。
4. 关联前引擎检查完整键频次/预计行数并拦截超限；结果报告新增左右重复键组数、膨胀倍数和每侧最多5个重复键样例。多对多不自动去重；先核对粒度，需要汇总时右表先加工并“保存为数据集”，再回来关联。
5. “保存流程”只保存规则；“保存为数据集”保存成功运行结果供后续关联。右侧关联选择数据集，不直接选择流程。

## 计算契约

沿用`derive`步骤，新增`{id,op:'derive',kind:'formula',expression:string,name,scale?:number}`；cast数值新增scale（默认6，整数0–12）。最大50步、表达式2000字符/120个AST节点，沿用任务时间、行列、内存限制。只解析AST白名单，不执行eval、用户Python/SQL、属性访问、索引或任意函数；未知字段/类型不匹配定位失败步骤。

字段引用使用稳定ID（例如c0001），不是可能重复的中文列名。数值常量最多26位整数/12位小数，超过引擎支持范围明确失败，不返回部分成功。十进制数学中间结果和输出按所选scale舍入，不使用浮点除法；除零返回NULL并计数。NULL传播，不默认补0，只有显式coalesce补值。不会推断财务币种/期间/收入成本口径。

| 功能 | 表达式示例 | 说明 |
|---|---|---|
| 多字段数学 | `(c0001 + c0002 + c0003) - 10` | 三字段先转换为数值 |
| 绝对值/舍入 | `abs(c0001)`、`round(c0001, 2)` | 输出小数位仍由scale控制 |
| 空值替换 | `coalesce(c0001, 0)` | 需相容类型，保留真实0 |
| 文本 | `concat(c0001, "-", c0002)`、`trim(c0001)` | 拼接遇NULL仍为NULL |
| 截取/替换 | `substr(c0001, 1, 3)`、`replace(c0001, "旧", "新")` | 截取从1开始；替换文本子串，与旧“精确值替换”区分 |
| 日期差 | `days_between(c0001, c0002)` | 两列先转日期，第二日期减第一日期 |
| 分组特征 | `group_sum(c0001, c0002)`、`group_count(c0002)` | 按c0002分组，保留明细行并重复展示组统计；无分组参数则全表 |

既有“条件分类”保留。分组特征不是分组压缩；标记nonAdditive并不对该计算列生成误导性的逐行相加总额。用户如显式再分组求和，仍须核对粒度，系统不替用户认定财务合理性。

## 删除与权限

新增POST `/api/v1/data-workbench/cleanup`，JSON `{kind:'dataset'|'recipe'|'job',ids:string[]}`，1–100个不重复ID。沿用菜单鉴权/CSRF和本人隔离。弹窗列出名称、确认操作、失败保留选择；成功只按服务端确认ID清理列表及相关预览/轮询。

- 原子批量软删除：任何一项不存在/越权/状态不允许，则本批不删除；不级联删其他对象。
- 数据集仍被未删除流程或任务（含历史任务）引用，409 `REFERENCE_IN_USE`返回具体引用。先处理相关流程/已结束任务，再删数据集。
- 任务排队/运行/取消中不能删，须先取消并等待服务端确认停止，409 `JOB_ACTIVE`；删除任务不删除其已保存为数据集的结果。
- 删除流程不删除源表或历史任务；删除后不能通过旧版本PUT恢复。已删除对象不再出现在列表或通过旧ID访问。
- 仅工作台本地元数据增加deleted_resources表，随原SQLite初始化建立，无需在MySQL执行DDL。保留不可变文件与元数据供审计，不物理释放磁盘，不动原Excel或业务库。文件保留/回收策略属于后续运维事项，不冒充已实现清盘。
