# 本地账号登录 V1 产品技术方案

状态：已确认并实施。更新日期：2026-10-10。

## 1. 产品目标与边界

登录首版解决“谁可以进入企业数据中心”和“谁可以管理账号”；2026-10-10 在此基础上增加菜单和智能投放岗位授权：

- 所有启用账号均可登录并使用现有业务页面；
- `admin` 可以新增、修改、启用、禁用和重置账号，并查看认证审计；
- `analyst`、`viewer` 均按普通用户处理；
- 不做部门数据过滤和企业微信登录；
- `sys_user_menu` 控制普通账号可见的一级业务模块；
- `sys_role`、`sys_role_permission`、`sys_user_role` 管理智能投放岗位与操作权限。

## 2. 现有表适配结论

### 2.1 `sibebid.sys_user`：满足账号主表条件

| 现有字段 | 本系统用途 | 结论 |
|---|---|---|
| `id` | 用户唯一标识、会话关联 | 直接使用 |
| `username` | 登录账号 | 直接使用，登录时转为小写 |
| `email` | 账号联系信息，唯一 | 新增和修改账号时必填 |
| `hashed_password` | bcrypt密码哈希 | 直接兼容，不保存明文 |
| `full_name` | 页面显示姓名 | 直接使用 |
| `role` | `admin/analyst/viewer` | `admin`拥有账号管理权限 |
| `is_active` | 是否允许登录 | 禁用后立即撤销已有会话 |
| `last_login_at` | 原系统登录时间 | V1暂不修改，避免影响原系统语义 |
| `created_at/updated_at` | 账号审计时间 | 新增或修改账号时维护 |

结论：不需要修改 `sys_user` 表结构。

### 2.2 `sibebid.sys_user_menu`：已启用

该表包含 `user_id`、`menu_code`，由账号管理页面读取和维护。普通账号只显示已授权模块；无记录时仅显示工作台，管理员忽略此表并显示全部菜单。菜单只负责模块入口与前端路由，智能投放的关键写操作仍由后端岗位权限强制校验。

### 2.3 仍需补充的认证扩展表

| 表 | 作用 |
|---|---|
| `auth_user_security` | 首次改密、连续失败次数、临时锁定、密码更新时间 |
| `auth_session` | 服务端登录会话、4小时闲置、24小时绝对到期、主动撤销 |
| `auth_audit_log` | 登录成功/失败、退出、改密和管理员操作记录 |

旧版试运行产生的 `auth_user` 不再读取；确认没有其他系统使用后可另行手工归档或删除，本次升级不自动执行破坏性删除。

## 3. 角色与权限

| 能力 | admin | analyst/viewer |
|---|---:|---:|
| 登录和退出 | 是 | 是 |
| 修改本人密码 | 是 | 是 |
| 使用现有业务页面/API | 是 | 是 |
| 查看账号和认证审计 | 是 | 否 |
| 新增、修改、启停账号 | 是 | 否 |
| 重置他人密码 | 是 | 否 |

后端必须校验管理员角色，不能只依赖前端隐藏按钮。系统禁止管理员取消自己的管理员身份或禁用自己，并保证至少保留一个启用管理员。

## 4. 页面

- `/login`：用户名和密码登录；
- `/change-password`：首次登录强制改密，也支持主动修改；
- `/admin/users`：管理员账号管理和认证审计；
- 顶部用户菜单：账号管理（仅管理员）、修改密码、退出登录；
- 全局路由守卫：未登录跳转登录页并保留原访问地址。

账号管理支持：新增用户名、姓名、邮箱、初始密码和管理员标记；修改姓名、邮箱、角色、启用状态；重置密码。管理员新建或重置的密码为一次性初始密码，用户下次登录必须修改。

## 5. API

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/api/auth/status` | 公开 | 判断账号系统是否已配置 |
| POST | `/api/auth/login` | 公开 | 校验bcrypt密码并创建会话 |
| GET | `/api/auth/me` | 已登录 | 当前账号和CSRF令牌 |
| POST | `/api/auth/logout` | 已登录 | 撤销当前会话 |
| POST | `/api/auth/change-password` | 已登录 | 修改本人密码并轮换会话 |
| GET | `/api/admin/users` | admin | 账号列表 |
| POST | `/api/admin/users` | admin | 新增账号 |
| PATCH | `/api/admin/users/{id}` | admin | 修改姓名、邮箱、角色或状态 |
| POST | `/api/admin/users/{id}/reset-password` | admin | 重置初始密码并撤销旧会话 |
| GET | `/api/admin/audits` | admin | 查看认证审计 |

除健康检查和登录相关公开接口外，现有业务API全部要求有效会话。

## 6. 会话与安全

- 浏览器只保存随机会话Cookie，不保存角色和长期JWT；
- 数据库只保存会话令牌SHA-256哈希；
- Cookie使用 `HttpOnly + SameSite=Lax`，HTTPS环境开启 `Secure`；
- 修改类接口校验独立CSRF令牌；
- 4小时没有有效API活动后会话失效；
- 单次登录达到24小时后强制重新登录，不因活动继续延长；
- 连续5次失败锁定15分钟；
- 密码至少8位且包含字母和数字，bcrypt限制UTF-8不超过72字节；
- 禁用账号、管理员重置密码、本人修改密码都会撤销旧会话。

## 7. 部署与数据库权限

应用读取和维护 `sys_user`，并维护三个 `auth_*` 扩展表。数据库账号至少需要：

- `sys_user`：`SELECT/INSERT/UPDATE`；
- `auth_user_security/auth_session/auth_audit_log`：`SELECT/INSERT/UPDATE`；
- 自动建表开启时需要认证扩展表的 `CREATE` 权限；没有DDL权限时由DBA先执行 `docs/sql/local-auth-schema.sql`，再设置 `AUTH_AUTO_CREATE_TABLES=false`。

账号密码不放在 `.env`。只有当 `sys_user` 完全为空时，才允许通过一次性bootstrap环境变量创建首个管理员。

## 8. 验收标准

1. 现有 `sys_user` 启用账号可以使用原密码登录；
2. bcrypt密码可校验，数据库和日志中没有明文密码；
3. 普通用户不能访问任何管理员接口；
4. 管理员可完成账号新增、资料修改、角色调整、启停和密码重置；
5. 禁用或重置后旧会话立即失效；
6. 闲置4小时和绝对24小时规则均生效；
7. 业务API未登录返回401，前端统一回到登录页；
8. 登录和账号操作有审计记录；
9. `sys_user_menu` 空表不会影响现有菜单显示；
10. 不应用部门或行级数据过滤。
