## 1 已确认范围和待定参数

- 用户确认检测验价请求数和生单请求数同时为0，不使用成功数替代请求数。有请求但失败不属于本规则。
- 先站内提醒，数据运营经理每天收到一份异常汇总，不附逐条航线明细，不接企业微信。分析证据保留站内按需查看，不重复建设航线诊断页面。
- 3天、7天是候选窗口，不是已批准的正式告警参数。最小查询量、按窗口累计还是按日设门槛、试点资源范围、日报时点和接收账号仍待确定；每日摘要先按站内展示设计，不默认新增总监自动通知。
- 业务对象候选为平台、站点和有向标准航线；资源范围明确记录GDS与通道集合。GDS/PCC/接口组作为诊断拆解，不把单PCC缺下游请求写成整个平台无产出。
- 自动限流/下线、白名单修改、技术执行、航线查定比、损失归因、错误原因采集及通用消息中心不在首版范围。既有白名单与MPIS调整复盘需求保留，不由本任务替代。

## 2 数据可用性核对结果

此处的“存在”只表示仓库定义或产出列存在，不表示线上字段非空或数据完整。证据编号见第8节。

| 数据层 | 平台和站点 | 航线和阶段指标 | 静态结论 |
|---|---|---|---|
| DWD查询、验价明细 | 两份DDL定义`otacode`、`otasitecode` | 有`airroute_code`等字段；分钟脚本含查询与验价/生单汇总分支 | 具备来源定义，真实归属值和各方法覆盖待验证，不能承诺历史可回补，见E01 |
| GDS 5分钟航线汇总 | DDL未声明平台/站点；分钟产出分支尾部写入`otacode`、`otasitecode` | 有航线、方法、请求量；查询分支出到达机场被写NULL，验价分支保留机场 | DDL与位置写入的列契约存在版本差异；不能用仓库DDL重建后直接声称链路兼容，见E02/E03 |
| GDS小时航线汇总 | DDL定义`ota_code`、`ota_site_code`；小时脚本SELECT、GROUP BY及INSERT均保留 | 保留航线、GDS/PCC、接口组、`api_method`、请求量及`min_retime/max_retime` | 优先复用候选，但依赖分钟层实际结构对齐；不是已经验证可运行，见E04/E05 |
| GDS日航线汇总 | DDL及日聚合均未保留平台/站点 | 有航线和三阶段基础量，聚合包含城市及机场 | 不能从该粒度恢复平台归属，不能把平台总量与航线总量拼接，见E06 |
| MySQL GDS资源服务表 | 有平台/站点 | 无航线字段 | 可辅助同范围总量对账，不能提供平台站点航线联合事实，见E07 |
| 应用航线服务 | 要求日表具有平台/站点 | 按航线、城市、机场、平台/站点、GDS/PCC聚合，默认Top500 | 代码契约与仓库日聚合不一致；缺列时应失败，不代表生产表一定缺列；不能把返回列表当全量检测源，见E08 |

还存在时间字段差异：小时DDL使用`min_retime/max_retime`，应用日航线服务要求`operator_mintes_max`；日脚本又按位置写入截取后的时间。复用需制定显式列映射，不应只替换`GDS_ROUTE_HIVE_TABLE`配置指向小时表。

### 航线匹配的首要限制

分钟查询分支明确把`dep_airport/arr_airport`写NULL，验价分支则保留机场。应用当前将城市和机场一起作为聚合维度，可能把查询和下游请求拆到不同记录。因此，上一轮“机场对可直接作为首版对象”的假设不能采用。

首版优先评估有向城市对归一化：分别对查询、验价、生单映射同一城市编码，保留机场作辅助证据，不按航司字段拆查询量。该粒度是实现建议，映射覆盖和业务适用性仍需验收；映射失败进入未归属集合，不用空串合并，也不强行猜测机场。若业务必须使用机场航线，需要先补查询侧机场信息或可靠映射后再开放。

## 3 小时数据复用方案

复用结论为“有条件可行”，而非“已就绪”。小时DDL和DML均保留目标维度，优先于从已丢维度的日表反推；没有必要把航线高基数明细扩入现有GDS查定比服务表。

建议链路：经核验的小时分区 → 保留平台/站点的独立日级派生指标 → 共享3天/7天滚动计算 → 现有事件及站内摘要。明细留Hive，少量检测结果和证据供应用读取，不按规则重复扫描全量小时数据。

复用前必须通过以下门槛：

1. 对齐分钟DDL、分钟位置写入、小时DDL和小时产出，确认字段名、顺序、类型及部署版本一致，不把历史DDL直接执行到生产。
2. 验证三个阶段的平台、站点和规范航线覆盖；空键、未知码及映射冲突单独统计，不混入正式命中或静默删除。
3. 明确`search`、`verify`、`orderCreate`及应用兼容的`order`别名。别名须结合实际来源确认，不能因过滤未识别方法而判0。
4. 按Asia/Shanghai界定业务日，将小时分区`dt`按其实际小时格式归日；记录各预期批次及阶段的完成状态。最大接收时间、24行记录或分区存在都不能单独证明完整。
5. 核对可用历史及保留期。单个7天窗口需要同一对象连续7个可判定日；比较多个窗口结束日还需要更长历史。DDL不证明7天历史实际存在。
6. 基础量先按真实维度聚合，再做城市映射及必要维表关联；检查重复行、映射一对多和总量变化。不要使用字符串拼接的旧`merge_code`替代规范业务键。

若小时数据缺字段或历史已过期，优先检查仍保留平台/站点的更上游数据；只能从真实可用的数据回补。无法恢复的日期标为不可回测，不将其填成0，也不承诺从当前日表重建历史。

## 4 候选规则对比与场景推演

### 统一计算约定

以下是用于静态比较的候选定义，不是正式启用参数。对同一对象、同一资源范围和同一窗口结束日，取最近K个连续自然业务日，K为3或7。

- 各日平台/站点/航线可归属，批次和阶段完整，查询量`Qd > 0`。
- 窗口查询量`SUM(Qd) >= N_K`。
- 窗口验价请求量`SUM(Vd) = 0`且生单请求量`SUM(Od) = 0`。
- 质量未知优先返回“待补数据/未归属”，不返回“正常”或“命中”。完整日确实无查询则不满足本次连续条件；不能跳过这一天拼成连续窗口。

| 对比项 | 3天窗口 | 7天窗口 |
|---|---|---|
| 观察条件 | 连续3个完整日均有查询且无两个下游请求 | 连续7个完整日均有查询且无两个下游请求 |
| 最早可判定时间 | 连续条件满足3日且数据完成后 | 连续条件满足7日且数据完成后 |
| 短期波动 | 更容易包含近期短暂现象 | 持续性要求更严，但业务有效率未验证 |
| 数据要求 | 至少3日同粒度可判定历史 | 至少7日同粒度可判定历史，缺日影响范围更大 |
| 样本门槛影响 | 累计量较小，可能未达到N | 同一累计N下更容易达到样本量 |
| 首版定位建议 | 候选观察标签 | 候选持续标签；不是自动高风险或自动处置等级 |

不能先验认定7天命中必然少于3天，也不能认定7天误报更低。如果两窗口使用同一个累计N，连续要求与样本门槛产生不同方向的影响。比较持续性时应同时输出纯持续条件结果和样本门槛过滤结果；`N_3/N_7`或每日门槛的最终选择由回测及业务确认，不在此固定。

### 十组合成场景结果

仅验证候选判定逻辑，不是历史命中量或业务准确率。样例将`N_test=100`作为两个窗口共同的累计门槛；D1最早、D7最新，除特别说明外，各日查询100、验价0、生单0且数据完整。100不进入生产配置。已在内存中逐项核对下列预期，没有运行应用或ETL。

| 用例 | 合成变化 | 最近3天 | 最近7天 |
|---|---|---|---|
| T01 | 7日均为默认条件 | 命中 | 命中 |
| T02 | D4有1次验价请求 | 命中 | 不命中 |
| T03 | 每天查询仅20，其他不变 | 样本不足（查询60次） | 命中（查询140次） |
| T04 | D7有1次验价请求 | 不命中 | 不命中 |
| T05 | D7有1次生单请求 | 不命中 | 不命中 |
| T06 | D3数据未完成 | 命中 | 待补数据 |
| T07 | D6完整但查询为0 | 不命中 | 不命中 |
| T08 | 对象平台/站点/规范航线不可归属 | 未归属 | 未归属 |
| T09 | D6数据未完成 | 待补数据 | 待补数据 |

十组均与上述候选定义一致。T03说明同一累计N会混入窗口长度效应；T06/T10说明3天可判定不代表7天数据就绪。实际命中对象数、关联查询量、人工复核有效率、误报/漏报及计算耗时均未测得，不能用本表推算。

### 后续真实回测输入和输出

不要求本轮查询数据库。后续可使用获授权的脱敏离线导出：逐日规范对象、资源范围、Q/V/O、三阶段覆盖与批次完成状态、映射版本和源批次；不能只交Top500、已命中清单或期间累计数。

比较时使用共同的窗口结束日和资源范围，分开报告“两窗口均可判定”的公共集合与“只有3天可判定”的短历史集合，避免把数据不足当未命中。输出3天独有、7天独有、两者交集、样本不足、质量排除、新增/持续对象、查询关联量和人工判定原因。先比较N相同的结果，再单列按日均或不同N进行的敏感性分析，不能把改变门槛的差异全部解释为窗口效果。

真实样本经数据运营经理标注业务有效性后，再决定正式K、N和试点范围。若需要验证后续是否出现下游请求，还须有窗口结束日之后的观察数据，不使用未来信息参与当时命中判定。

## 5 数据风险和处理要求

| 等级 | 风险 | 首版处理要求 |
|---|---|---|
| 阻断启用 | 日表丢平台/站点，应用却要求这些列 | 不能使用旧日表直接生成平台航线异常；先完成源契约对齐 |
| 阻断启用 | 分钟DDL与产出列不一致，小时依赖这些列 | 核验实际部署版本和字段顺序；不从DDL存在推断任务成功 |
| 阻断启用 | 查询机场为空，三阶段按机场或原始航线码聚合可能分裂 | 统一有向规范航线键并验证映射；不可归属不参与正式命中 |
| 阻断启用 | 某日或验价/生单阶段未完成却显示0 | 完成证明覆盖日、范围和阶段；缺失返回未知，不自动下结论 |
| 一般 | 空平台、空站点被NVL合并为一个组合 | 保留质量集合与影响查询量，不能伪造平台归属或静默忽略 |
| 一般 | Top500截断、维表重复、重跑累计、规则重叠 | 全量检测、关联前后对账、幂等写入；经理摘要按稳定对象去重 |

### 数据和接口最小要求

- 日派生指标至少保留业务日、平台/站点、规范航线键及粒度、资源拆解维度、Q/V/O和质量/源批次，不按接口组重复分摊同一汇总。
- 检测证据包含规则版本、K/N及门槛模式、结束日、逐日基础量、完成状态、首发及重算记录；经理汇总按对象去重，不把不同窗口查询量相加。
- 现有规则、事件详情与状态接口可扩展复用，但须同步扩展模板白名单、粒度校验、计算器和展示。站内发件箱不等于已有日报收件界面。
- 异常清单和每日摘要查询能力沿用`/api/v1/resource-governance/gds/...`领域，具体路由在实现契约中定稿，不登记为现有可调用接口。查询参数区分业务日、窗口结束日、执行时间、规则/资源范围，返回分页总数、覆盖和质量状态。
- 沿用RBAC功能权限，经理按授权处理、总监默认查看摘要，规则修改不默认授予。当前无平台行级隔离，若业务要求隔离需单独设计，不能只在前端过滤。见[权限边界](../access-control.md)。

### 首版验收用例

1. 双零请求且连续天数/样本满足时命中；任一阶段有请求即不命中，即使成功数仍为0。
2. 完整无查询、缺日、缺阶段、空键、未知映射、仅3日历史分别返回正确状态，不跳日、不补0。
3. 查询城市与下游机场通过已确认映射对齐；跨PCC下游存在时不误称整个平台航线无下游。
4. 超过500个对象仍全部检查，规则及窗口重叠时事件和摘要不重复累计。
5. 同日重跑不重复事件或日报；补数、规则修改、持续/解除条件均可追溯，不把解除条件误作已验证治理收益。
6. 日报只含汇总；无权限用户直接调用接口仍受限；既有查定比、OTA质量和演示页面不受新规则污染。
7. 数据完成及参数确认后再小范围启用；失败可暂停新检测/摘要，不删除历史事件、不执行生产控制。

## 7 交接和启用门槛

本轮已固化交付范围、静态字段差异、候选逻辑和验收要求，不固化未经确认的正式阈值或上线日期。下一步可先提供脱敏离线样本和实际字段说明，完成F01的数据核对及F03的真实候选比较；本次不要求生产库访问。

正式启用需同时满足：规范航线及业务范围确认、三阶段数据完成可证明、K/N与日报接收/时点确认、隔离验收及角色权限通过。3天观察、7天持续只是候选呈现建议；不默认两套都正式推送，也不自动升级为处罚等级。
