## 1. 使用方式

新建主单上方填写下发方、ADM号、原币总额、日期和主单说明；最底部“＋添加订单”，同一主单可录入三条订单，分别填写平台、出退改、订单/票号/PNR、币种、分摊金额、问题及处理计划。订单区可折叠，可移除未保存草稿。先存空主单也允许，但不能据此发布或结案。

例如三条订单分别需要恢复编码、申诉和不申诉说明；分别保存说明、后续分配及附件，不把三条结果拼到一段备注。初始计划不是已处理结果，不接受通过建档传入完成/审核/财务/持锁状态。金额可待核实，不自动平分、不把总额复制到每条订单；异币不直接相加。结案继续执行既有证据、审核和金额校验。

当前API已支持create的lines数组，主单和初始订单一次原子保存；本轮补前端入口，引用新建只接受本次重新填写的订单，不复制旧订单和旧完成事实。附件继续在保存后的主单/订单详情上传，不宣称原子保存涵盖文件上传。

## 2. Java字段逐项保留

静态核对来源：`flight-manage-api/src/main/java/com/ndccloud/flight/manage/entity/adm/domain/AdmRecords.java`（43个声明字段）及同目录上级`excel/AdmRecordsExcelVO.java`（44列）。数据库真实DDL、外部字典、继承基类和历史关联表尚待核对，不能用注释证明实际表关系。

下表为目标映射/补齐清单，不代表字段已全部能编辑或已迁移。现有38/44列导入把原值留在source.fields中，只是保留证据，不等于完成业务映射。原编码、显示名称及原值都保留，禁止用空值覆盖。

| Java字段 | 中台目标与保留方式 |
| --- | --- |
| id | 独立新ID，另存sourceSystem、旧id、迁移批次及来源修订；不拿旧id覆盖新主键 |
| admNo | 主单ADM号；不能仅以ADM号合并不同下发方或不明确的历史记录 |
| supplierCode, supplierType | 主单下发方编码、名称与类型分开；现supplierName不等于supplierCode，需补正式字段及字典映射 |
| airline | 航司字段保留；多值不凭逗号与其他多值字段做笛卡尔组合，主单/订单适用范围分别核实 |
| otaCode, otaOrderNo, ticketNo, pnrNo | 订单明细平台编码/名称、订单号、票号、PNR；组合关系不清楚列待核实，不能猜配对 |
| ticketCount | 保留原票号数量；新计算数量单列核对，不以订单条数自动替代 |
| totalAmount, currency | 主单原币金额及币种，精确十进制；分摊只在明确对应关系后录入 |
| totalAmountCny | 原人民币金额独立保留，缺汇率/日期不能重算或填0；需补正式业务字段/展示 |
| pnrRecoverTime | Java新增有PNR且此值为空时自动写服务器时间＋48小时，故不能当实际恢复完成时间。保留旧值及该语义，目标区分恢复时限与实际完成时间，不能据此自动完成 |
| supplyIssueDate, admDeadline | 下发日期、回复截止，原始值与规范时间均可追溯，不按迁移时间重置 |
| category | 票务/业务/客服大类编码、名称保留；不是businessType出退改，需独立字段/字典 |
| diffType, diffSecondType, diffDetailReason | 差异一级、二级及细分原因，映射订单的分类及差异说明，保留旧编码与文本 |
| owner, actualOwner, actualHandler | 当前处理人、实际责任人、实际处理人分开；不能合并成一个ownerName。旧姓名匹配当前账号前人工核对，不自动授权 |
| lockFlag, lockOperatorId, lockOperator | 原锁及操作者只作历史；切换后重新接单/持锁，不能继承旧登录会话或锁权限 |
| admStatus | 原处理状态保留，映射中台主单/明细状态需区分历史导入与新单录入。不能把所有历史结案单变成待办，也不能仅凭一个数字通过当前审核 |
| appealStatus, appealResult, appealReason, appealTarget | 是否申诉、成功/失败、原因及多对象映射申诉记录；历史缺轮次按实际来源留一条历史记录，不编造过程 |
| resolution, handleTime | 原结案结果和处理时间保留；不当成新系统本次办理、付款或验收时间 |
| auditorName, auditorTime, auditorRemark | 历史审核人、时间、备注；与中台新审核动作分开，不用迁移操作人替换原审核人 |
| fileUrl | 原地址留存并列出文件迁移清单；实际文件复制、大小/hash、权限和可读性核对后才算附件迁移成功。不得直接抓取任意历史URL或假设长期可访问 |
| status | 有效/无效/暂停与业务处理状态分开；无效/暂停记录保留，不因导入重新激活 |
| remark | 原备注、后续补充和覆盖意图分开，禁止空列清除或拼接覆盖原内容 |
| createTime, updateTime, createUserName, updateUserName | 原创建/修改时间与人员完整保留；另记迁移时间/执行人，新审计不冒充旧操作日志 |
