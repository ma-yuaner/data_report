# 用户行为监控 V1

状态：2026-10-09由用户确认启动开发。用户负责在MySQL `sibebid`执行建表语句，应用不自动建表。

## 目标

记录已登录用户主要访问页面、有效活跃时长、关键操作、查询成功/失败和页面流转，用于判断页面使用率与体验问题。低访问量不直接等于页面不好用，应结合加载耗时、失败率、无数据率、快速退出和下钻转化判断。

## 数据边界

- 用户身份与登录会话只由后端读取，前端不能指定`user_id`或`session_id`。
- 不采集密码、Token、订单号、票号、乘客姓名、上传文件名或具体筛选值。
- 筛选上下文只保留筛选字段名、日期跨度、分组、排序、结果数量等白名单信息。
- 登录页和修改密码页不埋点；管理员行为监控页本身可以记录。
- 页面访问每60秒更新一次活跃时长，路由切换和关闭页面时尽力补写离开状态；异常关闭可能只有`last_active_at`。

## 表和接口

DDL：`docs/sql/user-behavior-telemetry.sql`。

- `sys_user_page_visit`：一次进入页面一行，保存页面、来源、活跃时长、加载耗时、设备尺寸和有效操作数。
- `sys_user_behavior_event`：关键操作与查询结果事件，使用`event_id`幂等去重。
- `POST /api/v1/telemetry/visits`：开始页面访问。
- `PATCH /api/v1/telemetry/visits/{visitId}`：心跳或结束访问。
- `POST /api/v1/telemetry/events`：最多50条事件批量提交。
- `GET /api/v1/admin/telemetry/dashboard`：仅管理员可读取监控看板。

## 看板

菜单：系统管理 → 用户行为监控，路由`/admin/behavior`。

看板提供访问次数、使用人数、覆盖页面、平均活跃时长、平均加载耗时、查询失败率、无数据率，以及页面排行、用户主要页面、访问路径、日趋势和最近行为。原始数据按UTC保存，页面按Asia/Shanghai自然日查询。
