# 产品评审工作台架构1.0

2026-10-29。用户批准优化评审协作架构；此授权不表示GDS新治理口径已确认或可以执行真实上下线。实际实现由主会话明策/星桥完成，未派子代理。

## 运行结构

```text
门户模块目录 → 独立原型入口（Vue / Ant Design Vue）
                    ├─ 原AppLayout / 原业务Vue组件
                    ├─ 原型Vite别名：本机HTTP、账号、导出
                    ├─ 正常/空记录/部分同步/错误/权限演练
                    └─ 按需展开：组件PRD / 需求与设计工作台

registry.json → 编号关联检查 → 设计工作台数据 / Markdown / HTML / OpenAPI摘录
真实Vue模板 → 组件定位定义 → 点击/聚焦定位组件PRD
```

`frontend/src`本轮不修改。`frontend/prototypes/adm-review/live/LiveApp.vue`直接引用原`AppLayout.vue`。`live/contract-tools.mjs`在原型专用构建中把原布局的router-view改为slot，并展示原菜单结构；原型的菜单可见性不作为权限模拟依据。业务操作仍使用本机角色与接口适配。原页头导出抽屉由Vite精确别名替换成本机抽屉，轮询方法无操作，不运行正式导出服务。模拟退出只回到本机说明，不清理或调用真实登录系统。公共样式沿用原main.css，仅在原型范围约束高度和滚动。

默认全宽演示；显示PRD后左右分栏，拖拽沿用公共PanelDivider。原系统没有独立多页签框架，本轮不另造页签或新增业务菜单。未接入的原菜单只显示说明。原业务弹窗/抽屉仍在左舞台内打开。

## 单一维护源与追溯

结构化设计位于`frontend/prototypes/design-review/registry.json`：来源、需求、规则、页面、字段、接口、表及场景。每类使用稳定ID；需求链接来源/规则/页面/接口/表，字段反向链接需求。`generate.mjs`检查引用完整性，生成工作台数据、`docs/product/modules/resource-governance/design-baseline-v1.md`、可独立阅读HTML及`openapi.review.json`。

生成检查只能证明编号可解析，不能证明业务正确或数据实际存在。自动组件标注用于定位，并非需求覆盖证明。当前完整链路覆盖GDS六项需求；ADM仍是既有342项组件说明，未补齐全链路。其他模块尚未接入。

已有字段与候选字段明确分开。候选请求关联ID、生效版本、命中结果、预期/实际通道、回退原因和内部配置ID只是数据需求，类型、原始列、唯一键及存储来源未确认，不生成DDL。现有MySQL/Hive表名依据代码默认值，实际库表可配置，未连接数据库核验。

## 接口与模拟

保留已有`features/resource-governance/api.ts`调用，专属Vite别名替换HTTP。`resource-review/data.ts`适配已有三个GET接口，未知接口直接拒绝，没有生产回退。OpenAPI摘录是已有接口的可导出评审描述，仅覆盖公共字段；完整前端类型与服务代码仍是代码证据，不宣称接口全量schema或正式鉴权已验证。

`design-review/runtime.ts`提供五种可切换场景；选择后重挂载当前演示页，故明确提醒未保存窗口会关闭。场景只改变模拟响应，不改变原型业务记录；正常场景可恢复。零记录与错误分开；部分同步只作用于GDS总览，分母和比率为NULL；权限场景由模拟接口拒绝，不冒充真实服务端鉴权。白名单优先级、MPIS回退、查询转化窗口和上下线均待业务讨论。

当前本机别名已能满足离线交付，不新增MSW/Storybook/Backstage依赖；未来线上多人评审或跨运行环境共享模拟时，再评估MSW。在线托管、共享意见数据库及身份体系尚未实现。每人localStorage意见仍需导出交接。

## 构建与交接

在仓库根目录执行`npm --prefix frontend run package:product-review`。脚本依次生成原菜单、组件PRD及设计索引，进行相关Vue类型检查，打包门户和独立HTML。输出仍在仓库上级的“产品评审台”。设计包与OpenAPI可在工作台本机下载。

新增模块时复用本布局/右栏，把需求和关联实体纳入结构化定义，保留真实组件路径与数据缺口；不要建立第二套系统菜单或从页面倒推正式规则。当前生成器按GDS模块组织，其他模块接入时再扩展注册，不提前建设通用低代码引擎。

文档与代码同仓库，不建立外部目录软链接，避免拉代码后缺文档。独立文档仓库适用于多个项目共享，届时需明确版本对应和跨平台路径维护。

本轮必要验证为Vue类型、静态构建、编号关系与模拟数据关键不变量。用户自行操作验收，不扩展浏览器矩阵；浏览器实际布局/拖拽未验时明确列出。代码实现、推送、部署与业务验收分别报告；本轮不部署或发送通知。
