# 通用数据标注 V1

2026-11-22。入口为中台「数据标注」。ADM 是首个项目类型，通用项目可配置自己的标签。本模块使用现有登录及 CSRF 机制，独立持久化标注项目、样本及发布记录。

## 使用闭环

1. 系统管理员授予「数据标注」菜单，项目创建人另需「创建标注项目」。创建 ADM 或通用项目，按中台账号设定标注员、复核人。项目负责人可分配待标注和退回样本。
2. 标注员上传 PDF、XLSX、TXT、CSV 或 DOCX，可逐份成样本，也可合并成一组材料。项目内按附件内容指纹集合查重。项目负责人可在 ADM 项目引用已获权限的 ADM 原件。引用将原件复制到所选项目，项目成员随后按标注权限查看，源业务数据及解析记录不变。
3. 填写平台和标题。PDF 支持在原件选字、快捷标注、高亮回看。表格按工作表行展现，文字文件按行或段落展现。标题证据、字段标记和整份文件标签各自独立。ADM 不再预置 ARC、BSP 模板标签，现有默认标签从标注页和标签配置中隐藏，历史标签仍可随样本集回读。一处原文可用于多个标签，提交时按原文位置去重计数。当前支持每样本 1 至 300 个标记。
4. 点击保存草稿后写入服务端，提交前须填齐标题及来源平台，并至少有一处有效字段证据。位置数由服务端去重生成，兼容字段 `expectedPositions` 在新提交时同步为实际位置数。标签定义变化后，标注员须重新核对并保存草稿。提交后进入待复核，专员可以继续下一份。复核人可通过或填写原因退回，保留此前提交版本。提交人与复核人须为不同账号。
5. 项目管理员可从队列删除待标注和已退回的样本。确认后保留原件、标注版本及删除审计，队列和项目汇总不再计入该样本，相同原件可再次导入。
6. 项目负责人选择已通过的样本发布固定版本，单次 1 至 100 份且数据集不超过 20 MB。复核人和负责人可导出其中的人工预期、字段字典、来源位置、原件指纹和版本。原件下载继续服从项目权限。
7. ADM 项目可将已发布样本和原来件的现存解析候选做对照。只有 ADM 来件当前允许访问并有候选时才提供结果。当前覆盖 ADM 单号、航司编码、开具日期、正式罚款金额、币种、原因、票号和 PNR。原因比较选中片段是否出现，其余比较字段值。结果保留每条人工预期、实际候选及匹配、缺失、不同三种状态。对照不运行模型、不生成训练结果，也不改写解析候选。独立上传的文件显示未关联 ADM 来件。

## 发布和存储

- [建表脚本](../sql/data-annotation-v1.sql)手工应用于中台 `MYSQL_DATABASE`，先用核验 SQL 回读 5 张表及注释，再按中台 API/Web 发布流程更新。回退 API/Web 时保留独立标注表和文件。产生删除记录后，回退的 API 也须支持过滤 `deleted` 状态，避免旧队列统计失败。
- Compose 使用现有持久卷中的 `/app/var/adm/annotations` 独立目录。按权限将标注存储与数据库一起备份。原件按 SHA-256 寻址。同组文件每份限 20 MB、单次最多 10 份且总计 50 MB，沿用已有的读取、页数、解压和文本上限。扫描 PDF 需先 OCR。
- MySQL 使用现有中台连接池。SQLite 接口仅在明示 `TESTING` 和专用临时路径时启用。流程不连接模型服务，无新增 Worker。文件内容和 JSON 导出按项目权限处理，导出用于内部回归或后续受控训练。
- PDF 证据存浏览器选区和按页归一化坐标。服务端统一 PDF 字形和空白后核对引文是否出现在相应页，并校验坐标范围，按唯一引文位置或归一化坐标去重。精确高亮落点由复核人在原版面确认。若浏览器与服务端 PDF 读取顺序不同，可缩小选区或切换文字视图。普通文字的选区偏移以 UTF-16 码元为单位。

## 数据字典

SQL 脚本为每张表和每列提供中文元数据注释。除位置数量与版本为整数、事件时间为 DATETIME、JSON 为 LONGTEXT 外，标识与文本长度以脚本为准。时间均为亚洲上海业务时间。

| 表与列 | 使用规则 |
|---|---|
| `annotation_project` 的 `id,name,owner_id,kind,version_no,labels` | 一行一个命名唯一的项目。负责人为中台账号，项目类型 ADM 或通用，版本从 1 递增；标签 JSON 存字段及文件两个层级的稳定 ID、名称和说明。ADM 种子字段保留解析对照键。 |
| `annotation_member` 的 `project_id,account_id,role,display_name` | 一行一个项目成员，两列组成联合主键。账号必须已获菜单授权；显示名仅显示，权限按账号和角色判定。 |
| `annotation_sample` 的 `id,project_id,fingerprint,creator_id,assignee_id,status,version_no,updated_at` | 每项目每材料组一行。项目与指纹联合唯一，保存与流转在事务中按版本更新。标注员仅可见被指派样本。 |
| `annotation_sample` 的 `name,title,platform,source_task_id,expected,position_count,payload,segments` | 名称来自导入文件；标题平台空串表示待填，来源来件 NULL 表示非 ADM 引用，预期数 NULL 表示未设置。草稿保存和提交时同步预期数与实际数，历史发布值原样保留。实际数由服务端去重计算。内容 JSON 记录原件、标记、文件标签及复核；原文段落 JSON 在导入后固定。 |
| `annotation_revision` 的 `sample_id,version_no,action,actor_id,occurred_at,note,snapshot` | 每次导入、指派、提交、复核或删除一行。样本及版本为联合主键，备注空串表示未填写；提交和复核时保留证据、人员和标签快照，分配时记录被指派人。 |
| `annotation_dataset` 的 `id,project_id,name,created_at,creator_id,sample_count,payload` | 一行一个不可变发布包，同项目发布名称唯一。JSON 含人工确认的样本及当时标签版本，后续编辑字典不回写已发布版本。 |

## 验收范围

- 验收和试点重点为账号隔离、原件读取、版本冲突、防重、异格式附件、中断后的草稿回读、退回重提、发布后快照固定及对照查询。
- 当前迁移由部署人员在批准环境手工执行。未经目标库元数据回读和目标环境烟测，不得宣称生产已经启用。
