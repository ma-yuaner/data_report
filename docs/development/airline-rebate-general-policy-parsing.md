# 通用航司后返政策解析

## 配置和权限

API 服务使用原有 AIRLINE_REBATE_PILOT_ROOT 持久卷，数据库仍为现有 SQLite，不需要迁移。管理员上传和核实。只在确定允许向所配置供应方发送合同后启用 AIRLINE_REBATE_MODEL_ENABLED，地址为完整 HTTPS Chat Completions 接口，不接受重定向、凭据 URL 或查询串。模型需接受图像内容及配置的 JSON 输出格式。独立配置使用 AIRLINE_REBATE_MODEL_URL、NAME 和 KEY，密钥仅由环境配置传入。模型默认关闭。

经批准使用与 ADM 相同的供应方时，设置 `AIRLINE_REBATE_MODEL_SOURCE=adm` 和 `AIRLINE_REBATE_MODEL_ENABLED=true`。后返从同一 API 进程读取已有的 `ADM_PARSING_AI_URL`、`ADM_PARSING_AI_MODEL` 和 `ADM_PARSING_AI_KEY`，沿用 ADM 的输出格式配置，使用后返自己的提示词、Schema 和页图。官方百炼 `qwen3.8-flash` 按 ADM 的做法关闭思考模式。JSON 对象模式同样会在服务端校验后返 Schema。继续使用后返独立配置时，来源保持 `dedicated`。

默认最多 12 页、PDF 上限 10 MB、正文上限 100,000 字符、渲染图片总和 12 MB、响应上限 1 MB。可在模板中配置页数和模型超时，仍受代码上限约束。超过任何限制会失败，不截断后继续解析。

## 运行与恢复

现有 API 进程负责解析，同一 SQLite 卷只允许一个活动执行。上传只保存原件和提交标识，页面轮询实际处理进度。进程停止后可打开政策列表恢复持久队列。有效租约最长 15 分钟；模型请求已发出但结果未落盘时，租约到期后标记为结果未知，不自动重发。已持久化的模型候选从校验恢复，已保存的政策初稿从准备 Hive 样本恢复，两者都不会重新调用模型。

同一次提交的 UUID 在前端失败重试时复用。重新选择 PDF 并提交生成新 UUID 和执行 ID。模型结果附服务端请求回执、响应指纹、执行 ID 和阶段时间。校验失败可下载原候选并重跑校验；要重新生成初稿，请主动重新提交 PDF。

## 证据与计算

模型对逐页材料生成版本化规则草稿。程序验证日期、币种格式、数值和档位边界，再确认引用是否在指定文字页唯一出现。扫描页视图可显示原页，视觉位置是待人工核实的候选；没有可验证文字时不伪造黄色定位。只有证实的原文才进入现有 PDF 高亮逻辑。

解析完成后自动从 Hive 出票宽表准备一条参考记录，保留完整字段目录、Hive 类型和允许展示的脱敏值。该记录用于认字段，可能不属于合同覆盖范围。准备失败保持失败状态，列表提供「重试准备参考记录」，不会重复调用模型。旧政策缺样例时在列表访问后自动准备。打开详情和保存核实只读取已存结果。

通用草稿确认后可从政策详情点击「创建任务」，也可在任务管理选择已确认的政策。默认以政策文件名作为任务名称，负责人可调整。创建时绑定原件，并保存合同信息、规则及证据的 V1 快照。任务详情可回读快照和下载原件。同一政策重复提交会返回已有任务。

通用任务显示「计算规则待接入」。服务端拦截通用任务的手动试算，定时刷新跳过通用任务。既有试点政策继续按原适配器试算，历史任务和批次可回读。

## 验收矩阵

| 场景 | 本地覆盖 |
| --- | --- |
| 文字、换版式、扫描和混合输入 | 合成 PDF 通过上传接口和解析任务，扫描页真实渲染后送模型替身 |
| 当前提交真实执行证据 | 本地 HTTP 视觉模型替身收到严格 Schema 和图片，保存调用回执 |
| 双击、主动重提、超时、JSON 损坏 | 同提交不重复，重新提交新执行，失败可追踪，候选可回读 |
| 重启、Hive 失败、保存核实 | 过期模型执行不重放，候选恢复和参考补取不发模型请求，核实只读缓存 |
| 旧政策、实际与计划日期错配、通用草稿误放行 | 定向回归覆盖，通用草稿禁止试算 |
| 真实业务模型、T43、扫描件目视核验 | 待部署及授权后的真实环境确认 |

补充验证：已对经配置的真实 Hive 完成只读单行查询，获得 1 行 204 列，只记录数量。真实 HKG26003 在本地完成 3 页预处理，未发送至模型供应方。


## 首批合同验收入口

在目标环境通过上述开关接入已经配置的 ADM 千问，或配置独立的后返模型。先用合成 PDF 通过政策解析入口确认能取得真实服务请求回执并生成草稿，再开始真实合同验收。业务验收从「政策解析」上传 PDF、对照证据确认，到「创建任务」后回读 V1、检查合同字段及规则是否完整带入。提取错误按合同逐条记录，现有核对页支持确认及 Hive 字段核实，条款改值尚待开发。


## 奖励费率表完整性

模型输入对需要视觉辅助的文字页，在独立 100,000 字符预算内附带保留列位置的布局文本。提示词要求逐行逐列抽取，显式保留档位、舱位、航线类别、含端边界和费率，并按原件倍率换算金额。普通合同仍需人工逐项对照，未建立通用表格覆盖检验。

HKG26003 已审核版式由既有专用 PDF 读取逻辑从原件生成 36 个费率单元格。模型原始候选保留，草稿中的费率行使用从原件重建的费率和证据。识别到该合同而原表结构无法匹配时暂停解析；未经过此校验且尚未确认的旧 HKG26003 初稿需要重新提交合同。既有已确认政策及任务版本继续按原快照回读。


## 多方案政策

新解析输出 `rebate-policy-2`。千问在同一次请求中先输出奖励方案清单及含数据的表格页，再为适用、计量、计奖、档位、排除和结算条款分别标记方案。适用于整个合同的条款置于合同通用组。续表保留同一方案标识，证据中区分表头、数据行和正文。

服务端拒绝没有有效方案归属的奖励规则、缺少奖励证据的方案，以及清单中缺少数据行证据的表格页。只有表头证据不能通过。清单来自模型，程序的页证据检查无法发现清单自身遗漏的方案，也不能证明通用表格逐格完整。证据仍需人工核对。任务 V1 快照保存方案清单和分组后的规则。旧初稿和历史任务继续可回读。


## HKG26003 请求缩减与诊断

只有先通过专用原件读取检查的 HKG26003 才使用精简请求。正文送文字，扫描或乱码仍可按需送图；千问抽取正文规则，不重复生成由程序重建的 36 格费率。其他合同保留通用输入策略。

模型停止原因区分达输出上限、内容过滤、工具调用及未知结束状态；连不上与等待超时也分别提示。可解析的供应商回执保存结束原因和可用的 token 数，显式重试会清除上一执行的当前回执。
