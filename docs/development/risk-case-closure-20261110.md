## 应用与数据口径

- 人工核查复用风控核对的订单入口。判有问题时填写实际盈亏原因和咨询状态。普通保存进入待认定池并打开该案例，直接计入在同一事务写入差错认定、完结和历史。核查无问题不新建、不跳转。已有单案改判无问题时归入不计入差错并保留历史。
- 新案例按当前 ERP 内部订单 ID 与出票日识别。列表优先显示 OTA 订单号，缺值回退业务订单号，其后显示带标签的内部 ID。跳转用内部 ID、出票日和案例 ID。历史多单案例保留原粒度，详情允许选择原单看证据，按整案跟进。未留存的实际原因、首次分类不从当前值回填。
- 记录进展进入跟进中，完结或调整认定须选择计入/不计入。无权账号只读。负责人为已登录核查账号的系统 ID，自动规则使用系统标识，列表和表单隐藏。原有历史、专项案例、规章链接保留。
- 航司取与订单目录相同批次的订单指标，平台取目录 OTA 编码。政策员和出票员取出票核对明细，按业务单号与 OTA 号关联。退票员按该订单出票票号与相同 OTA 号关联退票核对明细，去重展示，有多人时保留多人。历史多单或缺可靠关联时人员不猜配。人员取数和代表性查询耗时待目标 MySQL 验证。
- 首次分类锁定建案时的分类编码。旧系统案例可沿用原规则编码。最新分类随成功发布的订单日批次写入既有人工核实 JSON，失败回滚，缺匹配订单保留上次成功值。刷新仅更新最新分类和时间。已完结案例仍留在对应认定池，自动看板继续按现行当前证据口径。
- RLA028 新自动案例创建时直接计入并完结。RLB18 保留自动核对结果，停止按原因新建待认定案例，原历史记录保留。
