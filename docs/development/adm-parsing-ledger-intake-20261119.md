# 从解析来件登记ADM台账

2026-11-19。用户明确授权实现、验证并推送公司GitLab main；T43由用户逐步更新。基线0246f51。主会话承担磐石/星桥/明鉴职责，无子代理；按chief-of-staff/frontend-design与项目交付规范裁剪。跨模块写入采用事务、权限、重复和故障专项自检；独立审查未执行，不称独立验收通过。

## 业务路径

ADM解析上传同一ADM的一组原件，解析校验并保存后，在ADM任务台账点击“从解析结果新建”。按ADM号、文件名、航司名称/原件编码搜索待登记来件，分页20条。普通账号仅自己的来件，ADM管理账号可看全部，登记还须adm.create；页面和服务端均校验。

选择后复用现有主单新建窗口。带入主单号、正式金额/币种、开具日、已匹配系统航司和原因；真实票号可带入，虚拟票号仅保留在解析来源快照中，不能当真实出票匹配字段。原件截止日与报表日仍展示核对，处理截止时间由业务填写，不猜当日时间。业务补充/核对来源类型、分类、罚单原因类型、组长、处理时限和细分原因，勾选核对确认，再“确认登记并关联”。可修正主单字段，登记快照保留原始解析候选，正式台账以用户确认后的主单为准。

新建为现有主单优先流程：不凭解析航段生成金额分摊明细、不自动恢复PNR、不把未知币种附件费用加入正式金额。航司PNR/GDS编码/未明PNR、各航段、虚拟关联票号、费用和来源原文保存在登记时快照，台账详情可展开，全部原件复制为现有ADM_ORIGINAL公共附件。后续恢复编码、登记真实订单、责任办理沿用既有功能。

成功后解析任务写回caseId/internalNo/登记人/时间/解析版本，并退出待登记池；解析页可打开台账，台账详情可查看封存快照和关联解析来件（仍受原来件权限约束）。注册后阻止重跑模型和重校验覆盖已登记解析快照，模型次数不变。

## 接口与原子性

- GET `/api/v1/adm/parsing/pending?search=&page=1`：先按权限/未登记/校验通过和搜索过滤，再分页；不调用模型。查询词上限100字，大小写不敏感、按字面搜索，不把%当通配符。
- POST `/api/v1/adm/parsing/tasks/{id}/register`：`{version,confirmed:true,form:{...现有主单字段}}`，返回`{registration,alreadyRegistered}`。保留现有登录、菜单及CSRF守卫。
- 无新增表、列或DDL。复用adm_parse_task.payload的registration、admwf_case.line_defaults_json的parsingSource及现有附件/操作日志；现有case.idempotency_key唯一索引是数据库防重前置。
- 对来件行SELECT FOR UPDATE，再检查拥有者、版本、SUCCEEDED/SAVED及无error；用同一连接新建主单/汇率快照/日志、插入附件记录并CAS回写关联，一次COMMIT。旧手工/Excel建单和附件接口保留独立事务默认行为。
- 附件复制校验原SHA256和字节数；主单、附件或关联中途失败全部数据库回滚，任务仍可登记；确定的事务体失败清理本次副本。COMMIT回执不确定时保留副本，避免误删可能已提交的文件；先刷新再重试，相同来源幂等，不重复建单。断电可能留下未引用副本，不影响原件。
- 对同一来件行锁保证并发串行；对相同原件组合的内容SHA256集合生成台账幂等键，重复上传也复用原台账、不重复复制附件。并发唯一键冲突/死锁返回409，可刷新重试；已结束台账对应相同原件不另建，提示负责人核对。不同原件但相同ADM号不自动合并，沿用既有可重复ADM号规则，业务须核对。
