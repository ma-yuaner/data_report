# 账号、角色与权限

## 当前授权模型

系统采用“RBAC + 个人例外”：角色统一配置菜单和固定功能，一个账号可以拥有多个角色；只在少量特殊场景下对个人功能单独开启或关闭。

- 系统管理员：`sys_user.role = 'admin'`，拥有全部菜单、功能和账号管理权限。
- 普通账号：通过 `sys_user_role` 关联一个或多个 `sys_role`。
- 菜单权限：通过 `sys_role_menu` 继承。
- 功能权限：通过 `sys_role_permission` 继承。
- 个人功能例外：通过 `sys_user_permission` 配置 `ALLOW` 或 `DENY`。
- `sys_user_menu`：仅兼容历史账号的直接菜单授权，新页面不再维护。

有效功能权限计算为：`角色权限并集 + 个人ALLOW - 个人DENY`。个人未配置时为“继承”，会自动跟随角色变化。

停用角色后，已分配账号会立即失去该角色提供的菜单和功能权限。权限在每次请求鉴权时重新读取，不需要等待重新登录。

## 智能投放推荐配置

- 数据运营经理：`DATA_MANAGER`，负责数据运营审核。
- 业务经理：`POLICY_MANAGER`，张庆贤和皮军平均分配该角色；任意一人完成政策审核即可进入待认领，不是会签。
- 智能业务执行员：`POLICY_OPERATOR`，只能认领已完成审核的任务并登记投放结果。

## 数据范围

当前版本的数据范围为“全部业务数据”，未实现按部门、平台、站点等维度的行级隔离。菜单权限只决定能否进入模块，功能权限只决定能否执行关键动作，二者都不能替代数据范围控制。

后续启用数据隔离前，需要先确定稳定的元数据标签、各数据源字段映射以及跨业务表一致的过滤规则；不能直接用缺失或不稳定的部门字段模拟隔离。
